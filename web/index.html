ETM 执行轨迹

  
「ETM 执行轨迹」直接用 Zynq FPGA 接收目标的四位并行 ETM，不经过逻辑分析仪。先载入与目标 Flash 匹配的 ELF，连接 ZynqDAP，选择起点断点，再在「2 时钟 / 3 采集」里配置并采集。停止后由浏览器内的 OpenCSD 解码，右侧可看执行流、调用统计、火焰图、热点、ETM 包和可信区段；没有硬件时可载入内置 F103ZE 实板样例体验完整流程。

  
RTT 为什么分三种后端

  
    
    
  • WebUSB · CMSIS-DAP：零安装，页面上直接读目标 RAM 拿 RTT。只认 CMSIS-DAP 类探针（DAPLink、cherrydap…），不认 J-Link。
    • 
    
  • 本地桥 · OpenOCD / J-Link：J-Link 与 OpenOCD 都是本机程序，网页无权启动它们，需要一个本机小程序当桥（仓库 bridge/，双击启动，零 npm 依赖）。
    • 
    
  • 内置模拟目标：无硬件也能看效果。
    • 
  

  
RTT 使用要点

  
    
    
  • 固件里必须编进了 SEGGER RTT（SEGGER_RTT_Init() 会被自动调用）。
    • 
    
  • 控制块地址优先用 ELF 符号（载入 .elf 最稳），否则用「扫描控制块」在 RAM 里找 "SEGGER RTT"。
    • 
    
  • 同一个探针不能被两个程序同时占用：OpenOCD / pyOCD / J-Link 开着时，先关掉它们。
    • 
    
  • RTT 不重传：目标写太快会覆盖/丢弃还没读走的数据。「缓冲高位」的次数和峰值水位是最实用的
      过载信号（≥75% 就算高位）；「溢出丢弃」只在主机侧读指针落后时才算得出来 —— 两个数字都当下限看。
      主机读速受调试器限制（OpenOCD RPC 实测 ~17 KB/s），大流量场景优先用 WebUSB 探针。
    • 
  

  
工程生成（最后一个标签）

  
    
    
  • 把 Keil .uvprojx 拖进页面：器件、Flash 起址、PyOCD / OpenOCD 目标会自动填好，其余参数都能手改。
    • 
    
  • 勾选要哪些文件，右侧是实时预览；「写入文件夹…」选一次目录就能把多个文件直接写进去（Edge / Chrome），
        其它浏览器自动改走「打包 ZIP」。
    • 
    
  • 生成时在 uvprojx2cmake.py 的模板上固定套 4 项修正（RTT 范围收进 RAM、clean 不再删
        *.log、OpenOCD 的 -c 改双引号、去掉 SWO 目标）；对账测试验证的是"不带修正时逐字节相同"。
    • 
    
  • 网页不能静默写你的项目目录 —— 必须你亲手选一次文件夹；test_sram.bin 是 RAM 测试图案，不是固件。
    • 
  

  
RTT → CDC 转发（「RTT 转发」那一页，akaLinkPro 探针）

  
    
    
  • 让探针自己通过 SWD 轮询目标的 RTT 控制块、把数据塞进它的 CDC 串口 —— 主机只要读一个 COM 口，
        比主机侧轮询快得多（本机实测 2.4 MB/s）。
    • 
    
  • 这一页是纯输出：只有接收（ASCII / ANSI / HEX、时间戳、暂停、保存数据、记录到文件），没有发送。
    • 
    
  • 「连接探针」走探针的自定义 HID（usage page 0xFF00）；授权一次后页面会自动重连。
    • 
    
  • RTT 地址可以手填，也可以「载入 ELF…」从 _SEGGER_RTT 符号自动解析（和 RTT Viewer 一样）。
    • 
    
  • 启动转发后，在同一页「选择…」授权探针的 CDC 口并「连接」，数据就出来了；「停止」把该口交回 UART。
    • 
    
  • ⚠️ Cortex-M7（H743 / H7B3…）要给 AXI SRAM 地址（如 0x24000000）：DTCM 探针读不到。
    •
