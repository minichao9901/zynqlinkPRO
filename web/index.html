SWO 使用帮助

  
接线与上手断点与重复采集目标时钟带宽计算探针匹配文件与示例

  
1. 接线与上手
连接目标 PB3 / SWO → 探针 PB07 / VCOM RX，并连接 SWD 和 GND。使用 NRZ / 8N1。按录制侧栏从上到下操作：载入目标 ELF、选择 VCOM 并识别目标、添加并选择断点、设置 SWO 参数，最后运行至断点并录制。初次使用还需授权探针时钟；停止后页面自动分析并恢复 Trace / 探针接收配置。

  
2. 断点起点与重复采集
在“① 载入目标 ELF”选择与板上程序完全匹配的 ELF，确认文件名和指纹。载入后，“③ 添加断点”会列出函数：点击函数前的“＋”添加；也可以输入 b main、b main.c:81、b 函数名:行号 或地址，再点击“添加”。源码行按 DWARF 行号解析，空行或没有机器指令的行不能作为断点。可添加多个候选，在“④ 断点与采集起点”用圆点选择本次起点。
“复位并停在起点”会先做 AIRCR 软件复位，再运行到所选断点并暂停；它只复位并暂停，不会开始采集。目标停住后点击“运行至断点并录制”，页面会从当前起点准备并启动 SWO。若不先复位，开始采集会让正在运行的目标继续执行，等它下一次到达所选断点；默认等待 15 秒，选到已经执行过且不会再调用的启动函数会超时。采集正常停止后目标继续运行；想从程序开头再采一轮，先点“复位并停在起点”，再开始采集。
断点列表是本页的采集候选。采集时页面临时设置所选起点的硬件断点，命中后清除；原有 FPB 状态会保留。

  
3. CPU、Trace 与外部晶振
CPU 频率决定 PC 采样率和周期时间；Trace 输入频率决定 SWO 编码器的分频。读取 RCC 可以得到时钟源和 PLL / 总线分频，板上外部晶振或有源时钟的频率仍需提供。标注“自动推算”表示根据配置计算，不是测量晶振。
F103 / F407 的 SWO 输入来自 HCLK，与 CPU 频率相同。H743 / H7B0 在 PLL 模式下使用 PLL1 R 输出作为 SWO 输入，CPU 使用 PLL1 P 输出并另经核心分频；不能直接拿 CPU 或 HCLK 替代。页面读取 PLL1 的 M、N、FRACN、P、R 和核心分频，分别计算两者。调试组件的总线时钟和 SWO 引脚编码时钟也需区分。常见型号的 DEV_ID 可能由多个芯片共用，页面显示型号组，不能保证识别到封装和完整料号。未知型号只识别内核并提示未适配，不套用 F103 配置。
配置分工：目标固件决定 CPU 与 Trace 输入时钟，包括 H7 的 PLL1 P/R 分频；网页读取 RCC，并配置 SWO 输出波特率、PC 采样间隔及 ITM/DWT 等采集参数；时钟计算器只模拟频率、采样密度和带宽。计算器中的“与 CPU 相同”“CPU ÷2”等选项不会改动目标 PLL。目标程序需在录制期间保持时钟稳定；改变时钟后应停止并重新识别。

  
4. 从采样密度计算带宽
PC/s = CPU Hz ÷ PC 周期间隔
PC 字节/s ≈ PC/s × (无时间戳 5 B；带时间戳约 9 B)
异常字节/s = 进入 / 退出事件总数/s × 3 B
ITM 字节/s ≈ 有效载荷字节/s × 2（按单字节包估算）
所需 baud = (PC + 异常 + ITM + 其他 字节/s) × 10 ÷ (1 − 余量)
目标实际 SWO baud = Trace 输入 Hz ÷ (ACPR / CODR + 1)
72 MHz ÷64 = 1,125,000 PC/s。仅 5 B 的 PC 包就需 56.25 Mbaud，超过探针 30 Mbaud。间隔越小，采样越密，但需更多带宽，依然不能还原 ETM 的逐指令分支流。DWT 合法间隔是 64 或 1024 周期的 1–16 倍；输入期望 PC/s 时选择不超过期望值的合法采样率。
时间戳长度和频率可变，实际带宽还包含同步、睡眠等包；这里给出规划估算，溢出和接收错误仍以实测为准。

  
5. 探针接收波特率与时钟
UART Hz = 选定 PLL 输出 Hz ÷ SYSCTL 分频
probe baud = UART Hz ÷ OSR ÷ UART DIV
误差 % = |probe baud − 目标 SWO baud| ÷ 目标 SWO baud × 100%
自动匹配先选择当前时钟源与分频；必要时调整 PLL1。默认 UART 240 MHz，最高 30 Mbaud。软件不会调整承载 CPU 的 PLL0；PLL1 调整须经过共享消费者检查，最终以探针回读为准。下方显示实际使用 PLL0 或 PLL1 的完整路径。“授权时钟”是浏览器对探针 HID 接口的访问授权。

6. 记录、ELF、源码与实测示例
“打开记录”打开自己的 .swopc 或原始 .bin；“载入配套实测示例”同时载入仓库内的实测记录、匹配 ELF 和源码，不连接硬件。.swopc 保存采样配置、ELF 指纹和错误信息；原始 .bin 只有数据，只有确定数据包边界时才勾选导入选项。
完整 .c 保留源码行和采样注释；“导出简化.c”只保留 C/C++ 源码，去掉注释，合并连续重复的行及代码片段，缺口以空行分开。两种导出均重新解码全部原始记录，不受区间和 250000 条事件上限影响。简化导出需匹配的 ELF 与源码；未采样代码不会补齐，文件用于阅读而非编译。





ZynqDAP 工作台
浏览器直连
使用桌面版 Chrome / Edge，在 HTTPS 或 localhost 下打开。串口助手与终端共用所选 COM 口；调试、RTT 和烧录通过 CMSIS-DAP。RTT 转发与 J-Scope 使用本项目的 HID 控制。
ETM 执行轨迹
顶部直接进入“ETM 执行轨迹”。J7.16 接 TRACECLK，J7.15/17/18/19 接 D0/D1/D2/D3，J7.14 接地。载入与目标 Flash 匹配的 ELF 后采集；解码在浏览器 Worker 中运行 OpenCSD WASM。CM3 样例明确标记为仿真记录。
连接与质量
同一 COM 口不能同时被其它串口工具占用。烧录或调试会协调释放冲突的探针会话。捕获需检查同步、溢出、包序号和结束状态；页面支持的目标仍需要实板验收。
工程生成
载入 Keil .uvprojx 或手填项目参数，可预览并下载 CMSIS-DAP / pyOCD / OpenOCD 文件，或写入自行选择的目录。
