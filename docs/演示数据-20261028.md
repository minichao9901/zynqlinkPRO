# 演示数据（2026-10-28，`prebuilt/20261028_swd_jtag/`）

产物 bit `a36d7ad2…`、elf `432a66c9…`；FCLK 120 MHz，setup +0.252 ns / hold +0.053 ns。
板子：ZYNQ7020 + STM32F103 目标。

## 0. 先说结论：之前的"读变慢"是我的测试参数问题

第一次报的 4.0 MB/s 用的是 `--words 256 --depth 4`。历史上 4.46 MB/s 那组是
**1023 字块、depth 8**（`docs/流水线与块大小实验.md`）。按同样条件重测：

| 条件（SWD 60 MHz） | 读 | 写 |
| --- | --- | --- |
| 256 字、depth 4 | 4.05 | 2.69 |
| 256 字、depth 8 | 4.00 | 2.29 |
| 512 字、depth 8 | 4.64 | 4.21 |
| 1020 字、depth 4 | 4.60 | 4.47 |
| 1023 字、depth 8 | **4.77** | 写请求超 USB 包长，失败 |
| 历史最佳（1023 字、depth 8，旧构建） | 4.46 | 3.76 |

**按同条件对比：读 4.77 vs 历史 4.46，没有退化，反而略高。** 之前低是块太小，
每块一次的 TAR 写 + USB 往返把吞吐拉下去了。

## 1. 最终对比表（统一 512 字块、depth 8、32 轮）

| 传输 | 时钟 | 流水读 | 流水写 |
| --- | --- | --- | --- |
| SWD | 50 MHz | 3.93 MB/s | 3.82 MB/s |
| SWD | 60 MHz | **4.64 MB/s** | **4.21 MB/s** |
| JTAG | 35 MHz | 2.62 MB/s | 2.58 MB/s |
| JTAG | 50 MHz | 1.99 MB/s | 1.96 MB/s |
| JTAG | 60 MHz | **2.36 MB/s** | **2.35 MB/s** |

## 2. 分析

- **理论上限**：60 MHz、每字 46 个 SWCLK → 5.22 MB/s。实测 4.64/4.77 是 **89–91%**，
  剩下的是每块 TAR 写和 USB 组包。
- **块大小是最敏感的参数**：256 字块每 KiB 要一次 TAR+往返，写吞吐从 4.2 掉到 2.3；
  这也是我第一次报"写比读慢很多"的原因，不是硬件问题。
- **JTAG 50 MHz 的凹陷**（1.99 低于 35 的 2.62）：请求 50 MHz 时 FCLK 取 100 MHz，
  目标 AP 相对更慢，WAIT 变多；这是已知的分频问题，35/60 正常。
- **SWD vs JTAG**：同为 60 MHz，SWD 4.64 / 4.21，JTAG 2.36 / 2.35。JTAG 每字 35 位扫描
  加 IR/DR 导航，约为 SWD 的一半，符合预期。
- 写入 1023 字会超过 4096 字节 USB 包（4077+5），请求直接失败；演示用 512–1020 字。

## 3. HSS 与 RTT

| 项 | 50 MHz | 60 MHz |
| --- | --- | --- |
| SWD HSS 最高 | 1 MS/s，零丢点 | 1 MS/s，零丢点 |
| SWD RTT | 3.92 MB/s | 4.64 MB/s |

JTAG 的 HSS/RTT 板上仍取不到（probe 服务 JTAG 路径下主机多字 AP 写失败），
仿真值：RTT 1.44/2.06/2.47 MB/s（35/50/60），HSS 412/589/707 kS/s。
