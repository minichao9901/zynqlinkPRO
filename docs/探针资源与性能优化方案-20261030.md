# 探针资源与性能优化方案（2026-10-30）

本方案合并 ds 的 [RISC-V 与资源小结](探针RISC-V支持与资源小结-20261030.md)、
[HPM5301 流水排查](HPM5301-SBA性能原因与流水优化-20261029.md)，以及本分支的
[native-32 实测分析](orbtrace-area-native32.md)。
ds 的三次文档提交 `af965b5 / 45c4e33 / c3cef57` 已引入本分支；未引入实板失败的流水 RTL。
本文确定后续实施顺序，不表示这些优化已经实现。

**建议顺序：先验收当前 native-32 配对，再做诊断 RAM 化和 sampler FIFO，随后比较数据互联合并。
保留 CDMA 与 DDR 作为默认架构；去 CDMA、全 OCM 作为后续独立实验。
RISC-V 先处理时钟与错误恢复，再恢复单扫描流水，避免与面积改造混在同一次验证中。**

## 1. 统一基线，避免重复计算收益

| 对象 | LUT | FF | BRAM36 | 时序/验收状态 |
|---|---:|---:|---:|---|
| ds 的 SBA pipeline 构建 | 23,382 | 33,726 | 6 | placed 报告；流水功能实板未通过 |
| ORBTrace 优化前候选 | 24,419 | 35,219 | 10 | routed；trace 输入 hold 未通过 |
| 当前 native-32 + ETM | **19,228** | **27,858** | **10** | routed/bitgen；100 MHz STA 通过，实板待验收 |

三行不是同一功能配置、同一实现阶段，不能直接相减归因。
当前可复现的面积起点是源码 `b5bbd3b`、产物提交 `d7776df`，配对目录
`prebuilt/20261030_orbtrace_native32/`，manifest 包含本次 bit/ELF SHA-256。
已验收 HPM5301 性能基线仍是 `prebuilt/20261029_hpm5301_riscv/`；它的 120 MHz 上限
不适用于当前 ETM bit。切换目录不会切换板上固件。

当前资源：Slice 10,535（79.21%），control sets 951；BRAM 10/140、DSP 1/220。
FCLK 100 MHz：WNS +0.568 ns、WHS +0.024 ns；120 MHz setup −0.265 ns。
当前 ELF 限 SWCLK/TCK 50 MHz，TRACECLK 约束 50 MHz DDR、校准参考 200 MHz。
STA 通过仅指现有约束，旧 SWD/JTAG 部分板外 input/output delay 尚未完整建模。

## 2. 对两份建议的取舍与校正

| 建议 | 合并后的判断 |
|---|---|
| 先压缩 AXI 开销 | 认同；native-32 已实施，整机 LUT 已减少 5,191，不能再次计入未来收益 |
| 合并四条数据 AXI 总线 | 保留为下一阶段实验；当前四条共 **2,760 LUT**，旧估计“再省 2,000–3,500”不能沿用，合并后的互联仍有成本 |
| 控制面改为 AXI-Lite | `swd_controller.v` 已是 32-bit AXI-Lite；直接层 2,985 LUT 包含诊断/配置/路由等，不能全算作 AXI 从机开销。应查网表归因及外部 converter |
| 诊断快照/FIFO 用 RAM | 提为第一轮局部优化，保持功能与地址接口，优先利用 BRAM 富余 |
| 去掉 CDMA | 后置。packet engine 产出 PL BRAM 数据并不等于已经实现 DDR 搬运；生产固件仍调用 CDMA |
| 缓冲前移 PL、全 OCM | 可研究，但不是本轮降 LUT 的先决条件；先核算完整内存与 DMA 访问，再决定 |
| JTAG 时序切分 | 认同，但依据当前最差路径实施；当前最差 setup 是 SWDIO IDDR→SWD 状态寄存器，不应把所有降频都归因于 RISC-V 新逻辑 |
| RISC-V 单扫描流水 | 单独推进；当前失败变体不作为面积基线或交付物，不以偶发失败作为验收标准 |

### BRAM/OCM 容量纠正

BRAM36 是 **36 Kibit**，不是 36 KiB。ds 文档中 6 块约“216 KB”、134 块约“4.8 MB”
应分别理解为 216 Kibit 与 4,824 Kibit，即原始位容量约 **27 KiB / 603 KiB**。
当前用了 10 块，余 130 块：含 parity 位原始容量 **585 KiB**；按常见 32-bit 数据组织，
不使用 parity 位时约 **520 KiB**，还需考虑深宽、双口、碎片和时序，不能当成连续 PS RAM。
块容量依据 AMD [UG473 Memory Resources](https://docs.amd.com/api/khub/documents/9gZGbqBxtlKXxBfkBt~lAg/content)。

OCM 共 256 KiB（[UG585](https://docs.amd.com/r/en-US/ug585-zynq-7000-SoC-TRM/On-Chip-Memory-OCM)）。
只要求“BSS 降到 200 KB”不足以证明能装入；代码、只读/初始化数据、MMU 表、heap、各模式
栈、USB dQH/dTD/缓冲、调试记录与对齐都要一起核算。当前 ELF 的 size -A 核对值为：

| 当前 ELF 段 | 字节 |
|---|---:|
| .text | 82,720 |
| .ocm_text | 3,552 |
| .mmu_tbl | 16,384 |
| .bss（DDR） | 715,508 |
| .dap_trace（DDR） | 65,600 |
| .heap / .stack | 8,207 / 14,336 |

此表只是主要段，不能把 debug_* 段和磁盘 ELF 文件大小当作运行 RAM，也不能仅合计本表就
认定布局可用。当前调试记录和多数 BSS 仍依赖 DDR，全 OCM 需要实际 linker map 与峰值占用证明。

## 3. 面积优化实施顺序

| 阶段 | 改动 | 收益依据 | 风险与采用条件 |
|---|---|---|---|
| A0 | 验收当前 native-32 + ETM 基线 | 已有 19,228 LUT 与精确产物身份 | 先补 DAP/CDMA/USB 实板回归；ETM 实板等待接线，不伪造通过 |
| A1 | JTAG 诊断快照 RAM 化 | 9×32×32=9,216 bit；直接层 10,031 FF / 2,985 LUT | 保留 32 条、9 字段和 CSR；对照实际 cell，LUT/Slice/FF 与时序一起比较 |
| A2 | Sampler FIFO 改 BRAM + 预取 | 16×32×32 bit；本模块 352 LUTRAM | 净收益小于被替代存储加控制的实测差值；不能承诺省掉整层 2,429 LUT |
| A3 | 四条数据互联并拢 | dma/cmd/rsp/pkt 共 2,760 LUT，控制互联另为 1,921 | 新交叉开关/协议转换/仲裁仍占资源，综合和实板吞吐通过后才采用 |
| A4 | JTAG 扫描缓冲分段、控制集整理 | shift 1,328 LUT；951 control sets、Slice 利用较高 | 长扫描/LSB/最后一拍/返回相位全部保留；不能靠截短长度省资源 |
| A5 | 去 CDMA、全 OCM 等架构实验 | CDMA 本体 774 LUT，属于可测机会而非净节省 | 替代搬运的 CPU/总线/缓存/新逻辑成本计入，不并入第一轮 |

ETM 尚未接线不阻塞 A1/A2 的实现、仿真和面积对比；在实板 ETM 回归补齐前，相关候选继续
标注实验，不能替换已验收配对或宣称完成整体验收。

### A1：诊断存储的具体做法

- 先从网表统计 diag_* 的 FF、索引写使能和读复用成本，验证 9,216 个逻辑存储位实际映射。
- 比较：保持九组 RAM、打包为 32×288-bit 快照 RAM。后者逻辑容量虽小，端口宽度仍可能
  消耗多块 BRAM，不能按总 bit 数直接称为“一块”。
- 写存储与复位控制分开，只复位 head/count/armed/frozen；优先尝试同步读和可保持的
  AXI 响应寄存器。不为迎合旧一拍实现而让 RAM 输出再次变成大规模异步选择。
- CSR 地址与字段格式保持；明确未有效捕获行的读取语义，不依赖未初始化 RAM。
- 覆盖：arm/clear/freeze、第 32 条冻结、索引切换、读写同址、AW/W 分离、RREADY 停顿、
  捕获中复位。LUT 未降但 FF/Slice 明显改善的方案单独列为布局收益，不冒充 LUT 收益。

### A2：Sampler FIFO 的具体做法

- 保留 complete-sample 原子发布、时间戳+变量布局、head/tail 所有权。
- 增加同步 BRAM 读预取，只有输出有效时才允许 pop；核对最后一个变量和下一样本边界。
- 回归单变量 fixed-pipe、连续/稀疏 plan、WAIT/FAULT、停机尾样本、满队列反压、DAP 接管。
- 记录多用多少 RAMB18/36；BRAM 组织不合算或预取造成吞吐退化时保留旧版。

### A3：数据互联合并的目标拓扑

保留一个 PS 外设互联，合并 dma_bus、cmd_bus、rsp_bus、pkt_bus 为一个 **32-bit、2 入 4 出**
数据互联；第一版继续使用现有 CDMA、三个 BRAM controller、CSR/BRAM 地址，减少同时变化的因素。

| 主端口 | 允许访问 | 不允许访问 |
|---|---|---|
| PS GP0，经外设互联的数据出口 | CMD / RSP / packet BRAM | 不经此路径回环访问 HP0/DDR |
| CDMA M_AXI | HP0、CMD / RSP / packet BRAM | GPIO / SWD / ETM / CDMA 控制寄存器 |

外设互联继续提供 GPIO、SWD CSR、CDMA CSR、ETM CSR 和一个数据出口。
仅在需要的边界保留 AXI3/AXI4/AXI-Lite 和 32→64 转换；不能把整个数据出口降为 AXI-Lite
从而丢失 burst。新 Tcl 必须检查**内部** crossbar 位宽；重新审查地址段、connectivity 与 regslice。

并发测试覆盖 CPU 查状态/诊断与 CDMA burst 同时进行、命令上传、响应下载、packet 排空、
USB 背压、timeout/reset。比较仲裁等待与吞吐，避免更小的互联把所有访问串行化。
单个大 crossbar 未必比多个受限路由的小互联更省，最终以 routed 报告决定。

### A5：后置实验的进入条件

`DAP/Source/swd_dma.c` 的 swd_dma_upload/download_to/packet_to 仍依赖 CDMA，
`probe_stream.c` 通过 swd_dma_packet_to 把 PL bank 拷入 USB 队列。去 CDMA 必须先实现
PIO/PS DMA/专用搬运中的一种替代，再比较端到端时间、CPU 占用、缓存维护、包所有权和失败恢复。
774 LUT 只是本体成本；不能加上 A3 已计算的互联收益后重复报节省。

全 OCM 单独建立配置：先消除/缩小 DDR BSS 和 trace ring，确认 USB DMA 可达性与对齐，
再迁移 linker/PS init。PL 缓冲搬大、去 DDR 与降 LUT 是不同目标，不能未经测量绑定。

## 4. RISC-V 可靠性与性能单独推进

| 阶段 | 内容 | 必须达到的结果 |
|---|---|---|
| R0 | 引入严格 DTM 模型与故障用例，建立当前基线 | 首答无效/一深响应、busy、DMI/SBA 错误、TAP/DM 状态丢失可复现；严格模型不等于已在当前分支实现 |
| R1 | 慢速 JTAG 保持高 FCLK，半周期分频产生 TCK | 对照当前 100 MHz 时序上限设计时钟策略，1/10/24.5 MHz 及最低档回归，ARM JTAG/SWD/ETM 参考不受破坏 |
| R2 | 错误后有界恢复/重新 prime | 无效地址读失败后下一次合法请求成功；原错误仍上报，禁止盲目重放可能有副作用的写 |
| R3 | 再实现明确的 dmi_post 请求/响应所有权 | 首笔 prime、包尾 drain、SBCS 检查、最后一字与 MMIO 都正确，再比较每字扫描数与实测 MB/s |

ds 已测到故障后 dmcontrol=0；应分别跟踪 TAP reset、DTM 状态、DM 激活与写请求完成，
不要把这一观测直接当成所有目标上“TAP reset 必然清 dmactive”的通用前提。
参考 superlinkPRO 的语义必须结合代码许可和当前硬件接口，不能直接并入已失败状态机。
包边界批量检查不覆盖所有操作：单次写、RTT RdOff 和 MMIO 的提交仍需确认，读错不得继续发布样本。

性能比较固定目标、实际 TCK、FCLK、TCK/字和扫描/字。仅按 50 MHz/1 scan 对 60 MHz/2 scan
计算的理想比值是 1.67，不是 1.2；且两者都不是 HPM5301 实测约 24.32 MHz 的时钟。
1.5 MB/s 仅作为正确流水后的验证目标，不作为已有结果或由 FCLK 上限直接推导的承诺。
随机失败、故障后全灭、必须重载 bit 才恢复都不接受。

## 5. 每阶段的比较与交付要求

每项从相同父提交建立独立实验，先做该项与父版对照，选中后才串联下一项。
完成同样的实现阶段/参数比较，不将 placed 与 routed 混用；跨方案收益不直接累加。

| 类别 | 记录/验收 |
|---|---|
| 面积 | 总 LUT、logic/LUTRAM/SRL、FF、Slice、control sets、BRAM、DSP，关键层级与 converter 数量 |
| 时序 | 当前 100 MHz 工作点、120 MHz 探索结果、WNS/WHS/TNS/THS、最差路径；不放松 trace 输入约束换通过 |
| 功能仿真 | 对应局部用例，加 tools/test_probe_rtl.py、test_jtag_rtl.py、test_riscv_rtl.py、test_packet_engine.py；失败必须定位，不能以其它套件通过替代 |
| 生产固件 | tools/test_probe_host.py；修改相关协议后运行 Web 测试，保留复位/端点/队列所有权语义 |
| ARM 实板 | 同频同目标 SRAM 校验、SWD/JTAG、RTT/HSS 动态零跳点与 DAP 接管、CDMA/cache 自检、断连/复位 |
| RISC-V 实板 | HPM5301 低/中/高 TCK 正确性、故障后恢复、长时间读写校验；HPM6800 未连目标时不声称通过 |
| ETM | 接线前继续 CM3/字节对照/OpenCSD 回归；接线后补 F103ZE 同步/无丢失/ELF 匹配/实际流量，与其它 USB 通路并发 |
| 吞吐 | 固定加载配对与实际时钟，多轮比较同种统计量；稳定可重复的退化必须解释后再取舍，错误计数/损坏必须为零 |
| 产物 | 每项通过后提交本次 bit/ELF、source commit、构建选项、SHA-256、时序/面积/上板记录；未验收明确标实验，保留旧已验收配对 |

本轮方案只是文档合并，没有修改 RTL/固件或重建产物；现有配对与 SHA 保持不变。
建议下一次实施从 **A0 → A1** 开始；R0/R1 独立推进，不与 AXI 拓扑或 DMI 流水同时改动。
