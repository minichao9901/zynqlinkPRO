## 对最初“退化”的分析

八变量超载点曾在 3×1 秒窗口出现约 10% 吞吐回落。逐帧统计确认：无跳点时约15样本/包，
超载出现时间戳间隙后变为1样本/512B包，USB 包率和背压敏感性大幅上升。
没有据此缩队列、修改数据校验或直接归咎于 Thumb。

随后使用**完全相同 ELF、PS 初始化、实际 FCLK100MHz/TCK50MHz**，只更换旧/新 PL，
各跑 5×3 秒，完整数据、尾部计数、序号均通过：

| 周期 ticks / 请求率 | 旧 PL + 最终 ELF | 新 PL + 同一 ELF | 变化 |
|---|---:|---:|---:|
| 240 / 100kHz | 100,000Hz | 100,000Hz | 持平、均无跳点 |
| 200 / 120kHz（超载） | 40,524Hz | 40,716Hz | +0.47% |
| 192 / 125kHz（超载） | 40,475Hz | 40,570Hz | +0.23% |

先前约10%的差异未稳定复现；该超载模式对 USB/主机背压和运行条件敏感，不能当成
固定的 RTL 或 ISA 损失。保留原短窗数据，不用超载有效速率冒充零跳点容量。
SWD25MHz 的初次自动边界搜索也有波动；固定周期47 ticks（510.638kHz）在旧/新配对上
各 3×2 秒无跳点通过。更慢周期也曾偶发主机背压跳点，因此不能假设搜索结果严格单调。

[交叉配对](../../../prebuilt/20261031_baseline_pl_compact_ps_control/README.md) 明确标为旧 bit
复用的诊断对照，不冒充本轮新综合产物。相同 ELF 下旧 PL 的 RTT25/30MHz请求仍失败，
优化 PL 则通过，说明这两点的改善与 PL 实现有关；未把具体物理机制归为唯一已证实原因。

## 本轮发现并修复的问题

1. 第一版紧凑 ELF 的 SWJ payload 强转 `uint32_t*`。Thumb 在常见的 packet+2 地址生成
   `LDRD`，PS 进入 Data Abort，尚未开始写目标 SRAM。`f5c938e` 改成有界复制到对齐数组。
   保护页测试覆盖1～256位及不同对齐，修正版通过，父版本负对照发生 `0xc0000005`。
   原失败 ELF SHA、PS寄存器/栈/反汇编位置与日志保留，不能加载它作已验收版本。
2. 旧基线和紧凑 ELF 均出现 HSS STOP 的重复 STAT 序号、尾部样本计数差1。
   STOP 最后排空的部分包晚于 `hss_poll()` 快照；`cbedca2` 在排空后重新读最终序号/样本数。
   无队列、采样周期或正常采样路径变更。最终50MHz配对 **106个** HSS窗口、60MHz配对
   **72个**窗口，重复序号/样本总数不符均0，包括运行中计数器顺序检查。
3. 功能脚本原来只选择 DAP SWD，遗漏独立 HID 服务偏好，前组 JTAG 状态会影响冷启动测试。
   脚本现显式选择 SWD。保留最初失败，在每次预设为JTAG后连续3次完整重试均通过。
   这不是放宽错误检查或修改固件的传输偏好语义。
4. XSCT connect 偶尔先于 target inventory 到达；只在执行命令前有界等待目标选择，
   每次使用独立 Tcl 文件。最初工具错误及重测记录均保留。

最终120MHz方案共25项驱动任务，全部返回成功。覆盖14个 SRAM频点、两协议持续RTT、
HSS边界/八变量/动态计数器、USB重配置/背压/DAP接管、非对齐访问、16深度线性API、OpenOCD。
JTAG1/10MHz下旧策略将FCLK降至24MHz以下，HSS拒绝启动，旧/新相同；不是新增回归。
SWD的1/10MHz HSS诊断通过共享RTT设频路径进行，原始行明确记录公共HSS setter拒绝低频。

## 仿真、边界与复测

原生 RTL/C 回归保留于 [前期验证目录](../orbtrace-7010-ocm-20261030/)。
加密 DesignStart CM3 的21点采样矩阵在父版本与优化版各14点通过、7点同样失败，无新增失败；
这7点是不兼容的固定返回延迟/采样组合，不作为通过用例隐藏。
9个有效工作点的 SRAM/RTT/HSS 数据、计数及耗时周期与父版本完全一致。
仿真没有建模USB/PS指令吞吐；固定延迟模型的SWD30MHz另保留原失败和单独标注的校准点。
真实硬件使用实际自动校准结果，没有把模型参数硬写回板卡。

验证记录中的 `.bin` 为仅供恢复的临时 SRAM 副本，不纳入交付；JSON保留备份/恢复SHA及逐字节
一致性结果。bit/ELF与实际验收清单均已纳入Git。各次加载日志和文件SHA可与Git blob核对。原始 `git_dirty` 包含当时未跟踪的build/报告和测试脚本变更；固件身份以实际加载文件SHA及构建源码指纹为准，最终另做逐文件源码审计。

本轮没有合入另一 worktree 后续新增的 ETM 五线滤波/64K-record FIFO，也没有对优化bit做
真实ETM采集验收。相关主线改动合并后，需要重新检查面积、时序和ETM功能；不能沿用本轮数字
宣称合并后的7010仍能放下或已完成ETM验收。原已知可用配对保持不动。

复测必须先在对应器件加载明确的 bit/ELF/ps7_init 三件配对，再读取实际时钟。
主机脚本切换目录不会切换板上固件。使用新的输出目录保留旧证据；
`hardware-regression-plan.md` 与每个 `*_runs.json`/`runs.json` 保存调用方式，
`run_f103_jtag_fixture.py --restore-swj 2` 对当前调用 NOJTAG 的目标固件保存/恢复引脚与运行状态。
