## ZL-256 · Viewer 顶栏切换

Viewer 保持用户原设置 SWD 20 MHz 和 5 ms 轮询，复测走 `zynqlinkPRO / SWD MEM-AP`。160 次服务快照中，42 次正在执行 Viewer 自己的 `usb/exchange`，118 次为空闲，USB 会话全程打开。网页计数从 16,384 B 增至 868,352 B，`lost`、`corrupt` 均为 0，服务失败和取消计数未增加。原顶栏把任意当前服务操作显示为「操作中」，因此正常轮询每次恰好落在顶栏刷新时就出现黄灯。

源码按运行中的 Viewer、该 USB 会话身份和操作类型识别常规轮询，保持已连接状态。连接、复位、其他所有者的任务和传输错误继续显示，取消按钮也使用同一判断。此次复现和字节计数来自固定 EXE 原版，修订后的界面逻辑由 Web 回归核对。[顶栏状态](../../../web/app/ui/probe-status.js)

## ZL-257 · 转发选错接收口

原现场 Viewer 已断开，转发 HID 已连接，页面选中的是 `COM5`（CH340），接收计数为 0。主机枚举确认 `COM33` 是与 J7 HID 序列号相同的 CDC 口。Zynq 在普通转发模式等待自己的 CDC 接收端就绪才开始探测 RTT。选错串口时，页面仍把共享串口会话显示成「接收口已打开」，转发状态则给出控制块未找到的泛化提示。

在同一页面断开 COM5，刷新后连接 COM33。保持原控制块地址 `0x24000014`、通道 0、搜索长度 `0x1000` 和请求 SWD 60 MHz，重新启动即找到控制块和上行缓冲 `0x2400002c`。一次实读检查网页已收到 983,040 B，转发状态的读错和 RdOff 写错均为 0。退出 Viewer 后也再次启动并实收，随后复核页面确认接收口仍为 COM33，转发引擎已停，最近一次搬运计数为 333,254,656 B，读写错误均为 0。

源码在本机转发页优先选择唯一的探针 CDC 口，误选本机通用串口会给出明确提示。已有错误接收口或尚未打开 CDC 时，转发状态指出接收端状况。保留独立的探针 HID 启停和现有串口助手流程。[接收口选择](../../../web/app/hid/stream.js) · [转发状态](../../../web/app/hid/view.js)
