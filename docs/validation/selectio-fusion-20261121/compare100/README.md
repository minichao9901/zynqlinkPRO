历史 swd200 的 `842f2990` 分支报告引用最终 zero-idle 配对。F103 HCLK128、批内 idle 0、驻留 1 KiB 图案，三轮每方向 16 MiB 的读 / 写为队列 7.565 / 8.039、A9 本地 7.485 / 7.759。图案预装后翻转、逐字核对，PC 传输新载荷的时间在窗外。较早的 HCLK48、idle 2 纯 SWD 批次约 7.14 / 7.43。jtag200 分支 `dfb4e4d4` 的 HCLK48、idle 33、1 KiB 驻留交替短窗为 A9 本地 4.991 / 4.991；按每方向 2,491,392 B 除以原始 scan 约 0.4940 s，扫描段约 5.043 / 5.043。HCLK96/idle19、HCLK128/idle13 的本地分别约 6.081、6.713。历史源码工作树内的路径分别为 `docs/validation/f103ze-swd200-resident-20261119/README.md` 和 `docs/validation/f103ze-jtag200-20261119/hclk48-windows.json`。

单线 100 Mbit/s 的裸位率折合 12.5 MB/s。SWD 长流按每个 32 位字的 8 位请求、3 位 ACK、32 位数据、1 位奇偶和两次 1 拍换向计算。无 WAIT 时，idle 0 / 2 的净载荷上限分别是 400/46=8.696、400/48=8.333 MB/s。融合版一个 4,032 B 请求含 1,008 字，四个 TAR 段各另发 TAR、RDBUFF 和 CTRL/STAT。以 idle 2 计算，计入这 12 笔事务后的理想上限是 8.235 MB/s，还未计入段间停钟和返回采样。读段完成同时检查最后回采，缩短输出 idle 可以与等待返回重叠；短测支持读方向受回采尾部制约，确切停钟周期还需逐拍取证。[Arm ADIv5 B4.2](https://documentation-service.arm.com/static/622222b2e6f58973271ebc21?token=) · [SWD 段结束条件](../../../../fpga/rtl/swd200_segment.v) · [块结构](../../../../firmware/xusbps_daplink_dma/DAP/Source/selectio_block.c)

本实现 ARM 双 TAP 连续扫描每字用 43+idle 个 TCK，含 35 位 ARM DR、1 位 BYPASS、导航、保护和返回。idle 29 / 33 的稳态上限分别为 5.556 / 5.263 MB/s。方向长窗中，融合版 idle 29 的队列达到对应上限约 95.6%，PC 达到约 84.2% / 82.1%。SWD idle 2 队列约 87.3% / 90.6%，PC 两向约 74%。[JTAG 帧预算](../../../../fpga/rtl/jtag200_arm_stream.v)

按原 3 × 60 秒窗口折算每个 4,032 B 的服务时间，SWD 读 / 写队列约 554 / 534 µs，PS 块函数累计约 585 / 567 µs，主机累计约 653 / 653 µs。队列外合计约 99 / 119 µs，其中 PS 函数内约 31 / 33 µs，余约 68 / 86 µs 落在该计时边界之外，包含 USB 请求应答、固件帧处理、主机排队及载荷准备等。流水情况下这些是按载荷归一化的时间差，不能进一步当作独立 USB 总线延迟。JTAG 对应的两段增量约为 31 / 33 µs 和 73 / 91 µs。本次比较保持交付参数，零 idle 的数据属于短窗证据。

独立分支 `codex/jtag-only-200mhz`（`dfb4e4d4`）的 `docs/validation/f103ze-jtag200-20261119/f103-128-quad-pilot-windows.json.gz` 中，`points["100"].mixed[0]` 给出 idle11 成绩，`tck_hz` 为 100,000,000。该配对另有约 6.949 MB/s 的 1 秒只读通过记录。早期 idle13 看同目录 `hclk128-windows.json`。同板 HCLK96/TCK100/idle19 通过 3×60 秒交替和 3×60 秒只读，方向吞吐约 6.081 MB/s。该分支约 8.220 / 8.219 MB/s 的三轮持续峰值来自实际 TCK 125.490 MHz、HCLK128、idle13。

融合版每方向取三个长窗的中位数。PL 队列和 PS 分别按 `payload_bytes / probe_delta.queue_s` 和 `payload_bytes / probe_delta.probe_s` 折算，PC 直接取 `wall_MBps`。PS 内存服务到 PC 的差额覆盖计时范围内的固件帧处理、USB 和主机处理，共享流水下各计时差额不能直接当作单项延迟。 [融合版逐轮数据](../../spi-cdc-20261123/rx-guard-jtag-idle25-long.json)

以稳态每字 43+idle 个 TCK 计算，100 MHz 时 idle11、25 的理想值为 7.407、5.882 MB/s，后者低约 20.6%。同一融合配对下将 idle29 降至 idle25 后，PC 读写各提升约 5%。此前在 HCLK48、TCK100、idle33 下，独立版扫描段约 5.043 / 5.043 MB/s，融合版队列约 5.037 / 5.035 MB/s。两种证据一起支持优先比较 idle 和计时边界。融合版在 HCLK128、idle11 能否实现同样的短窗或长窗仍待同配对验证。 [融合版验收地图](../../spi-cdc-20261123/fusion-acceptance-map.svg)

同日后续实板复测已在融合配对确认 slot28/idle11。1 KiB 队列与独立版扫描段相当，4,032 B 跨页的 PC 成绩与分层时间见 [同条件复测](../../spi-cdc-20261123/jtag100-ab/README.md)。
