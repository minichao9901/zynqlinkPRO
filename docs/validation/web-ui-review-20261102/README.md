# Web 界面评审：紧凑工作台与渐进呈现

日期：2026-11-02（Asia/Shanghai）。源码基线：`22b0352`。本轮仅评审及登记，不修改产品代码、不重建 EXE。

## 设计约束与结论

用户明确要求：简洁、美观、易于上手，**工作区大、窄边框，顶部入口和状态保持同一行**。本报告以此为约束，不建议增加常驻左侧导航、大标题、双层顶栏或大卡片留白。继续保留默认打开烧录器的既有选择。

现有暗色、紧凑布局适合工程工具，主要改进空间在于信息优先级、上下文一致性和减少重复配置。建议采用“连接一次、按任务配置、数据占满、详情按需展开”。紧凑不等于每个选项都常驻；易用也不需要强制向导。

最优先的三项：ETM 历史分析释放采集侧栏；统一目标/ELF/连接上下文；串口与 RTT 补可检索的日志体验。视觉微调围绕这三项展开。

## 逐页建议

### 1. 串口助手

现状：ASCII/ANSI/HEX、快捷发送、定时发送、时间戳、保存数据、持续记录均已有。顶部显示选项和底部记录选项较多；“暂停”的实际含义主要靠 tooltip，“保存数据”与持续记录容易混淆。

- 默认连接区保留端口、波特率、连接；数据位/停止位/校验合成 `8N1` 摘要，流控及 DTR/RTS 放可展开高级设置。用户常改的 DTR 可固定显示，保留恢复后的真实值。
- 时间戳合成“关闭 / 相对 / 绝对”一个菜单；“暂停”改为“暂停显示”，暂停后在原工具栏提示仍在接收/记录及未显示的数据量。
- 区分“导出当前缓冲”和“持续记录到文件”，展示各自覆盖范围；不能因为收起选项而让用户误以为显示区等于完整采集。
- 高频补充优先：本地接收文本查找、过滤、关键字高亮；发送历史与命名命令组。现有快捷发送保留，不另造重复入口。文件发送可后置，需单独确定协议和速率控制。
- 过滤只影响显示，原始记录保持原字节；大数据查找应明确当前缓冲/完整记录范围。

### 2. 终端

现状：与串口助手共享同一个 `SerialSession`，但未连接时主要告诉用户去另一页设置；小量终端设置占用完整侧栏。

- 近期：在现有工具栏就地提供“连接串口”入口，调用同一会话配置；回显、回车、退格、字号收进终端设置，默认将空间给终端。
- 后续可把“收发助手 / 交互终端”作为串口工作区的两个模式，保留 `#terminal` 直达和快捷切换。是否合并需验证老用户切换成本；无需为合并增加一条常驻工具栏。
- 高频补充：终端缓冲查找、输出记录入口、连接断开后的明确恢复入口。目标 shell 的命令历史由目标维护，不能宣称前端已有或盲目代发。

### 3. RTT Viewer

现状：后端、目标类型、芯片、RAM 范围、控制块地址、轮询同时显示；已有 ELF 定位、控制块扫描、ANSI/文本/HEX、文件记录及下行输入。

- 首先修正 ZL-100 的上下文不一致。目标板应决定默认架构、接口及 RAM 范围，保留显式自定义；不要让用户维护相互矛盾的下拉框。
- 常规流程为“选目标/沿用目标 → 从 ELF 定位或扫描 → 开始查看”。手填地址、扫描区间、轮询和其它后端按需展开。
- 高频补充：与串口共用查找/过滤/高亮组件；命名配置；连接后清晰呈现可用通道、当前通道及上下行能力。需按后端能力呈现，不能把 J-Link ch0 限制掩盖掉。
- 页内解释“普通查看”与“高速转发”的选择条件。ZL-093 已记录 Web 路径速度差距，优化真实传输应复用既有问题，不以界面重命名宣称速度改善。

### 4. RTT 转发

现状：配置探针转发与打开 CDC 接收是两段操作，各自有连接/启动按钮；用户可能成功启动转发但仍看不到数据。左侧内容需要滚动。转发已有纯输出说明、保存、持续记录和质量入口。

- 保留两个独立状态，但以紧凑流程展示：“探针就绪 → 转发运行 → 接收口已打开”。失败明确指出停在哪一段。
- 在完成必要设备授权后提供“开始接收”组合动作，依次完成必要步骤；仍允许高级用户只启动转发，交给外部串口工具接收。
- 高频补充：关联探针与 CDC 端口、重新枚举后的端口提示、命名配置。无法可靠关联时让用户选择，不能随意打开另一设备的端口。
- 与 RTT Viewer 可以共享一组产品入口，但普通查看和高速转发应保留独立模式；切换前明确资源交接和当前流停止结果，不静默抢占。

### 5. J-Scope 波形

现状：已有采集/变量/触发/帮助分组、固定开始/停止、分道/叠加、A/B 游标、触发重找、CSV、原始包回放和质量面板。基础布局值得保留。

- 普通采集只展示变量、采样率/周期、时长和开始。数据端点、短批次、串口桥暂停、标定依据等转入高级设置；开启会影响串口的选项时仍给简短影响提示。
- “连接探针”和“连接数据端点”整合为一个连接流程，内部逐步完成必需授权；保留细分状态供排错。
- 工具栏常驻全览、缩放、分道、游标、导出；原始包与回放归一个记录菜单。底部保留样本数、实测速率和质量摘要，错误非零时显式突出，其余详情沿用质量面板。
- 高频补充：命名的变量/触发方案、通道单位和比例换算、A/B 区间统计（均值、峰峰值、RMS 按需选择）。已有游标和触发不能算缺失。
- 估算、标定和采样实测必须明确区分；现有 ZL-097 span 展示问题另按原编号处理。

### 6. 烧录器

现状：适合作为默认入口，但未选文件时右侧大部分是空日志；侧栏“路径”在 WebUSB 下不能使用，说明文案需要用户自己判断。已有 ID 读取、格式解析、进度、校验及烧录后复位。

- 空闲数据区提供明显的固件拖放区；选中后展示文件名、格式、实际加载段/地址范围、实际写入字节和目标。文件路径只在能读取它的后端显示。
- 主流程收敛为“固件 → 目标 → 烧录”，后端及高级时钟可折叠。“烧录”按钮旁概括校验和完成后运行/暂停选项。
- 原日志区在运行时显示阶段、进度和耗时，原始日志可展开；已有进度不需要重做成新功能。不能拿 ELF 文件大小当写入量。
- 高频补充：最近固件/目标组合、独立校验入口、烧录完成后“使用同一 ELF 进入调试”。近期文件复用需重新核对内容变化和文件访问权限。
- 后续能力扩展可考虑读回备份；是否允许读取、地址范围及后端支持需另外验证，不纳入首批美化。

### 7. 调试器

现状：已有源码、命令行、寄存器/内存/变量/SVD/RTT/异常面板、断点和栈帧，以及多个最大化入口；无需为“完整 IDE”再塞更多固定面板。

- 连接后可收起会话配置，保留紧凑目标/运行状态；源码占主区，命令行支持折叠到一行。复用已有工作区和分栏能力。
- 动作文案区分“指令单步”“源码进入/跳过/跳出”；保留 F5/F10/F11。避免“单步”和“进入”都需鼠标悬停才知道粒度。
- ELF、源码目录作为一个会话配置管理，显示是否匹配；镜像文件目录等低频操作放高级。
- 高频补充优先：命名工作区、断点/观察表达式随工程保存、源码文件/符号快速打开，以及变量到波形通道的显式添加动作。跨页传递的是符号和类型，目标不匹配时需重新解析地址。
- 寄存器/内存写入保留原值、编辑态和写入结果，防止“回车即写入”只靠小提示。不要对每次普通单步增加确认弹窗。

### 8. ETM 执行轨迹

现状：已有分步采集、记录选择、执行流/调用统计/火焰图/热点/包/可信区段、搜索定位、源码联动、区间缩放及 HTML/SVG 导出。打开历史记录后，左侧仍展示当前目标的载入 ELF、连接、断点，易分散注意力并占约 320px。

- 最优先：沿用现有“收起控制”能力，打开历史记录时默认进入分析布局，记住用户选择。当前记录的 ELF/源码和实时目标分别呈现，一键“新建采集”再展开设置。无需另建第二套页面。
- 默认保留常用分析入口；包级细节可进“更多分析”。质量摘要始终可见，严重错误和未知数据不能为了简洁藏掉。
- 记录选择改成可搜索列表/弹出面板，显示名称、目标、时间、时长、质量；支持重命名、标签、收藏。当前大量同型号加时间戳不便识别实验目的。
- 新采集提供“立即采集 / 从函数或断点开始”任务选择，只展示当前芯片和链路实际支持、已验证的方式；技术配置放高级。H743/F103 的入口、复位能力不可因统一 UI 而混用。
- 分阶段呈现配置、硬件采集、传输、解码/索引及目标恢复；没有可度量进度时显示当前阶段和耗时，不伪造百分比。
- 高频补充：区间书签和备注、按函数/异常导航的快捷入口、两条兼容记录的差异比较。现有函数筛选和区间导出应直接复用。
- 图上标清执行序号/有效周期的含义。调用权重、路径数不能标成耗时；缺少周期时禁用时间比较。比较功能还要检查目标 ELF、配置、时钟、统计口径和质量。
- 采集设置四个子页优化：目标页以起点选择为主，断点命令折叠；时钟页先给核对结果，RCC 公式后置；采集页保留时长和核心选项，TPIU/寄存器后置；文件页把“导入/保存记录”与“导出分析”分组，按当前视图给默认格式。

### 9. 工程生成

现状：已有工程文件/调试参数/本地桥分组、文件预览、单文件复制/下载、ZIP 和写入文件夹。默认勾选多种后端及 SRAM 图案，并在首屏显示模板来源、自测和修正项。

- 建议更准确命名为“工程与调试配置”，说明产物范围，避免被理解成从零生成完整 MCU 工程。
- 先选用途/工具链，仅展示相关参数和文件；保留高级多选，SRAM 测试图案默认不与普通调试文件捆绑。
- 原有实时预览保留；文件很多时用可搜索文件选择器，避免多排标签吞掉预览高度。长路径仍可复制完整值。
- 高频补充：配置保存/导入、生成前检查缺失路径和不匹配目标、写入前冲突列表及差异预览。不是删掉现有“不覆盖”保护。
- 本地桥保持独立高级分组；模板实现、自测命令、历史修正说明移至关于/开发者文档。

## 功能适配：减少配置次数

建议建立统一的“目标会话配置”：目标板、架构、接口、请求时钟、ELF 身份、源码位置及各工具专用设置。已有 probe manager、共享串口会话和 HPM 选择逻辑应复用，不再建立竞争的连接管理器。

共享的是已确认的上下文，不是把所有页的频率和运行状态强行相同。ETM、RTT、烧录各自保留能力边界；只在用户执行连接/开始时按规则交接资源，切换页面本身不停止采集或触发复位。显示时区分用户请求、寄存器计算和外部测量来源。

导入 ELF 一次后允许各工具显式复用；更换目标/固件后让旧符号、断点、变量地址失效并重新解析。保存配置不等于取得设备或目录授权，权限失效时说明需要重新选择。

## 实施顺序与完成标准

1. **第一批，收益直接且改动小**：修 ZL-100/101；整理过时和内部文案；明确暂停显示/持续记录；推广设置收起；ETM 历史分析默认释放采集侧栏。顶栏保持单行、边框宽度不增加。
