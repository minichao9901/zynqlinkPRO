# HPM6800EVK 工作台与 FPGA JTAG 验收（2026-11-09）

正式 J7 配对的 50 / 60 MHz 关键原生性能通过，AXI SRAM、RTT 和同口径 1 / 8 路 HSS 的最大历史偏差为 **0.717%**。66.667 MHz 实验配对重复达到原有峰值，1 / 3 / 8 路 HSS 均通过 60 秒零跳点。60 MHz、idle 19 的 SRAM 提速成立，RTT 长窗触发错误和后续配置残留；正式工作点保留 idle 20。Web 烧录、调试、Viewer 上行和 CDC 数据完整性通过已列用例，Wasm 10 ms 轮询存在明显主机错拍。

## 对象与边界

- 源码基线 `d36180e9cfc673f4a0912f4d27811301716bc740`。参考 [H743 验收](../h743-workbench-acceptance-20261109/README.md) 的功能范围、历史最佳 2% 比较门槛及严格低于 0.1% 的 HSS 跳点率，按 superlinkPRO `044af4a` 的 HPM 功能矩阵展开。本轮使用 HPM6800EVK 的 HPM6880 hart0，TAP `0x1000563d`，RV32，用户确认目标 NRST 未接。硬复位、引脚量测、ARM ETM/SWO 及板载外围功能均不适用。
- 初始 FPGA 未配置，探针 USB 未枚举。正式 J7 bit 经 RAM/JTAG 加载，SHA-256 `dd69106c46a4bd1a52badecbf9125e51beca8435c25d2742cca62323efaaf4e6`。正式 PS ELF SHA-256 `5895eeb0e79a3681a6b3b966dbea4c82ebfcd01ea7553e094d8a61ed2cf89802`，物理 MEM-AP0 核对 85,844 B。66.667 MHz 使用同 bit 与已提交的 [J7 实验 PS ELF](../../../prebuilt/h743-jtag66-20261109/README.md)，SHA-256 `daf4cf7275b7581ba62bf7eba2957e2587432495f96f625a16df3de683534c38`，核对 86,172 B。bit 约束 133.333 MHz / 7.5 ns，setup +0.067 ns、hold +0.044 ns，沿用已归档时序结果。
- 表中 FCLK/TCK 根据探针 PS PLL、分频和 PL 寄存器读回计算。25 MHz 是规格内档位，50 / 60 / 66.667 MHz 是单板超规格验证。原生性能工具直接使用 CMSIS-DAP、HID 和 COM52。Web 通过隔离 Edge 157 和本机 USB 代理运行 OpenOCD Wasm。两条路径分别取证。
- 原始 Flash 前 64 KiB、相邻 4 KiB 保护扇区和 Flash 算法使用的 128 KiB ILM 均在写入前双读核对。ELF 为已保留的 `dbgstress/fw.elf`，SHA-256 `f76305dbb023612d114585fb6152a95949a5768988014084a051341a238124da`。开测时应用代码段匹配，首加载段有 3,072 B 差异，最终恢复以物理双读备份为准。测试只写目标 XPI 前 64 KiB，未写探针 QSPI。

## 原生性能

SRAM 固定 512 words、128 loops，深度按 AXI / AHB / AXI 末 4 KiB 分别为 32 / 16 / 2。吞吐取三轮中位数，另各窗口随机与反相数据交替读写 10 秒，66.667 MHz 各 30 秒。RTT 为非缓存 AHB 中的 8 KiB 环、1024 B 搬运块，三轮 2 秒中位数，三个高速档另各 60 秒。每轮核对 SRAM 逐字节读回、RTT 连续 u32 序号及发布 / 主机实收总量，探针稳态搬运速率独立计量。单位为十进制 MB/s。历史对照使用 [R21 同档分档表](../hpm6800-speed-completion-20261102/README.md) 的原生路径。

| 实际 TCK MHz | FCLK MHz | idle / 模式 | AXI 读 / 写 | AHB 读 / 写 | 末 4 KiB 读 / 写 | RTT 2 秒 / 60 秒 |
|---:|---:|---:|---:|---:|---:|---:|
| 25.000 | 50.000 | 8 / 0 | 1.630 / 1.616 | 1.615 / 1.608 | 1.395 / 1.380 | 1.486 / — |
| 50.000 | 100.000 | 16 / 17 | 2.835 / 2.802 | 2.785 / 2.766 | 2.258 / 2.237 | 2.609 / 2.609 |
| 60.000 | 120.000 | 20 / 17 | 3.194 / 3.162 | 3.155 / 3.113 | 2.447 / 2.453 | 2.953 / 2.953 |
| 66.667 | 133.333 | 22 / 17 | 3.448 / 3.403 | 3.373 / 3.344 | 2.639 / 2.704 | 3.188 / 3.188 |

66.667 MHz 的 AXI 读 / 写、RTT 分别较同档历史三轮中位数低 0.131%、0.021%、0.003%。50 / 60 MHz 的 AXI、AHB 和 RTT 对照均在 2% 内。辅助的末 4 KiB、depth 2 墙钟偏差较大，50 / 60 MHz 写较旧样本高 10.60% / 11.98%，66.667 MHz 读较旧同档分档低 3.30%，较旧同档持续测组低 2.60%。这些对照的 PL 扫描数、移位位数和等待周期完全相同，变化落在 PL 扫描以外的墙钟时间。关闭浏览器及服务后，用同一实验配对复测末 4 KiB，九轮读中位数 2.654 MB/s（范围 2.636–2.688），较旧分档低 2.76%，写中位 2.622 MB/s，10 秒交替校验和恢复通过。排除 Web 在运行这一条件，主机 USB 与 PS 开销仍未分离。

### Idle 与故障恢复

- 50 MHz、idle 15 短测出现 DTMCS `dmistat=3`，16–18 通过，16 在本组最快。66.667 MHz、idle 20 / 21 均出现 `dmistat=3`，22–24 通过，22 在本组最快。两组失败点均恢复 DPC、SRAM 和运行状态。
- 60 MHz、idle 19 的三个 SRAM 窗口通过持续校验，AXI 3.241 / 3.207 MB/s，相较 idle 20 本轮成绩快 1.44% / 1.43%。同档 RTT 长窗随后失效，探针停在 40,332,288 B、两次读错误。下一条 DAP 标志写入失败，自动收尾报 `-4`，本轮将 idle 19 限定为 SRAM 工作点，RTT 及 HSS 的验证值仍使用 idle 20。
- 失败现场的 RTT/HSS 均不活动。独立低速恢复后核对 20,480 B AHB、256 B ILM、核心寄存器、cache 和时钟配置。刚恢复时心跳短暂持平，随后无需目标复位，三次暂停读回确认 PC 变化、心跳继续且 trap 计数为零。
- 错误后的 STOP 在低速返回 0，两个 STATUS 均回到 0，随后合法的原生和 Web 配置仍返回 `-7`。读取 [PS 状态机](../../../firmware/xusbps_daplink_dma/probe_stream.c) 可将拒绝范围缩小到配置守卫的待处理字段，现场还未区分 `pending_len` 和 `dma_pending`。重载相同正式配对后 Web CDC 实收通过，ZL-003 保持待定位。

### J-Scope 严格低于 0.1% 跳点

使用 24 MHz 调度时基，比较 1 / 3 / 8 个连续 u32。短窗搜索、三次 2 秒确认后，25 MHz 各做 10 秒，三个高速档各做 60 秒。下表为实得 k组/s，括号内是周期 ticks。最终每个窗口的逐值、数据帧、计数和停止尾差核对通过。

| 实际 TCK MHz | 1 路 | 3 路 | 8 路 | 长窗跳点率 |
|---:|---:|---:|---:|---|
| 25.000 | 137.931（174） | 38.400（625） | 26.085（920） | 0 / 0 / 0.0057494% |
| 50.000 | 242.424（99） | 67.606（355） | 45.977（522） | 三组 0 |
| 60.000 | 275.862（87） | 76.433（314） | 52.061（461） | 三组 0 |
| 66.667 | 296.296（81） | 82.759（290） | 56.338（426） | 三组 0 |

25 MHz 八路 920 ticks 的 10 秒窗跳了 15 点，符合本轮门槛。历史 1012 ticks 为严格零跳点确认值，两种门槛单列。高速档每路的边界点及更短周期失败见 [evidence.json](evidence.json)。

## OpenOCD 读写流水线的来源

本轮原生性能工具直接访问探针；旧修改版原生 `openocd.exe` 和当前 Web Wasm 是两套构建。旧 `cb0c224` [流水线补丁](../../../prebuilt/golden/host/openocd/pipeline.patch) 将在途请求 4→8，并将 `dump_image`、`read_memory`、`write_memory` 的三处 4 KiB 缓冲改成 64 KiB。历史 F103 同档读速 3.18→3.75 MB/s，证据在提交 `0a543143`。

当前 Wasm 字节与 superlinkPRO `c9454d0c` 一致，底层 OpenOCD 为 `9f2d876`。链接脚本只复用了 `dump_image` 64 KiB 的思路，另增加 32 位连续 RISC-V SBA 读合批与浏览器 USB 适配。在途上限和 `read_memory` / `write_memory` 的缓冲仍沿用该上游版本。HPM Web 性能不可用旧原生 F103 补丁的数据代替。 [Wasm 运行时来源](../../../web/app/core/openocd-runtime/README.md) · [链接脚本](../../../web/tools/dev/link-openocd-core-wasm.py) · [上游 CMSIS-DAP](https://github.com/openocd-org/openocd/blob/9f2d8762b3a75b4d7b2155affcf3d8bb8eb8849a/src/jtag/drivers/cmsis_dap.h#L22) · [上游内存命令](https://github.com/openocd-org/openocd/blob/9f2d8762b3a75b4d7b2155affcf3d8bb8eb8849a/src/target/target.c)

## 交接

离线通过 152 项 Web、65 项 CLI、159 个 JS 模块语法及共享驱动一致性检查。正式配对以物理 OCM 再验收，目标 XPI 前 64 KiB SHA-256 `a0f998fdfa7d3cde6bc2439fb46ab5a0d5f11a2258b50ec63211d3c0c92ca0db` 与开测相同，相邻扇区匹配。探针最终档位、应用心跳、清理清单和逐轮测量见 [evidence.json](evidence.json)。

最终目标运行原应用，J7 保留正式 RAM 加载配对，实际 TCK 约 25 MHz、FCLK 约 50 MHz、idle 8、模式 0，RTT/HSS/DDR/DMA 空闲。整个任务在工程外唯一临时目录完成，仓库只归档本报告、摘要证据和问题索引，原备份、诊断构建、浏览器数据、运行令牌与原始采集文件均纳入临时目录回收。

临时目录共 6,311 个文件、1,120,016,121 B，已移入回收站并确认原路径不存在。测试浏览器、工作台及本任务独占的硬件服务已退出。
