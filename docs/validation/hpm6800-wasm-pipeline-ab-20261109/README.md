# OpenOCD Wasm 块读流水线移植与 HPM6800EVK A/B（2026-11-09）

在当前交付 Wasm 对应源码上补齐旧流水线补丁。HPM6800EVK 实际 25 MHz JTAG 上，文本读的 20 / 64 KiB 中位吞吐较交付版提升 **1.76% / 1.92%**。二进制镜像读低 0.45%，写速最大下降 0.36%。全部 30 个读写用例逐字节通过，11 次独立读回含前后保护区，最终原 SRAM 和目标运行状态核对通过。

## 构建身份

- A 使用当前仓库 `9d852037` 的原始交付 Wasm，SHA-256 `098be8c32791c5a24573a605292aec2cfe7d1a7d2d0dacc030006a723b5918dc`。A′ 在临时目录重编原配置，控制工具链及链接差异。B 与 A′ 共用 OpenOCD `9f2d8762b3a75b4d7b2155affcf3d8bb8eb8849a`、Jim Tcl 和 libusb 固定提交、Emscripten 4.0.10、full / Oz 链接配置。B Wasm SHA-256 `1977164ce62a8595753be9dfa741751c0b3f2459a95aa6bd03f25afe72d554fe`，JS 加载器与 A′ 同哈希。
- [增量移植补丁](pipeline-port.patch) 把在途上限从 4 调到 8，将 `read_memory` 和 `write_memory` 的缓冲从 4 KiB 调到 64 KiB。`dump_image` 的 64 KiB 已由现版链接脚本实现，B 继续保留。RISC-V SBA 读合批与 USB 适配沿用现版构建。 [原流水线补丁](../../../prebuilt/golden/host/openocd/pipeline.patch) · [现版链接脚本](../../../web/tools/dev/link-openocd-core-wasm.py)
- MSYS2 的增量构建未因共享头文件变化重编所有传输对象。首轮及时剔除并核对 SRAM 恢复。正式 B 强制重编了 CMSIS-DAP 主驱动、USB Bulk 与 TCP 对象，逐项核对时间戳并重新链接。报告及结果中不使用首轮吞吐。
- 复建先按现版脚本配置源码和静态库，再应用本目录补丁并强制重编上述对象，最后用原链接脚本的 `--optimization Oz --profile full --browser-session` 生成 B。每次变更共享队列结构后应确认相关对象均重编。构建选项、完整哈希和分轮数据见 [evidence.json](evidence.json)。

## 上板口径和数据完整性

使用同一在板 J7 正式 bit/ELF。bit SHA-256 `dd69106c46a4bd1a52badecbf9125e51beca8435c25d2742cca62323efaaf4e6`，PS ELF SHA-256 `5895eeb0e79a3681a6b3b966dbea4c82ebfcd01ea7553e094d8a61ed2cf89802`，前后物理 MEM-AP0 各核对 85,844 B。各测量会话读回 FCLK 49,999,999 Hz、TCK 24,999,999.5 Hz、采样模式 0，频率由寄存器计算。TAP `0x1000563d`，HPM6880 hart0 保持运行，未操作 Flash、目标 PLL 或板级复位。

所有测量在同一非缓存 AXI SRAM 窗口 `0x0126f000`，最多 64 KiB，前后各 64 B 保护区。每轮用相同的固定种子初始值和改写值。A、B 各三轮交替，穿插原生对照三轮，A′ 另两轮。每轮预热、计时读写、逐字节校验写回，再由独立原生低速读回整窗及保护区。计时不含预热、独立回读和最终恢复。

无浏览器与工作台服务。Wasm 通过 Node.js 运行现版 OpenOCD 调度器，复用 Python/WinUSB USB 适配，墙钟包含请求序列化及结果转换。原生 CLI 对照复用 CMSIS-DAP `TransferBlock` 快路径，每包 2 KiB，20 / 64 KiB 对应队列深度 10 / 32。两者操作总字节数、地址和实际时钟相同，协议路径和批量粒度分别记录。

## 结果

吞吐单位为十进制 kB/s，均为墙钟中位数。

| 用例 | 当前 A 读 / 写 | 同源重编 A′ 读 / 写 | 补丁 B 读 / 写 | B 对 A 读 / 写变化 | 原生 CLI 读 / 写 |
|---|---:|---:|---:|---:|---:|
| 20 KiB 文本 | 31.24 / 34.37 | 31.23 / 34.43 | 31.79 / 34.76 | +1.76% / +1.12% | 1589.47 / 1582.52 |
| 64 KiB 文本 | 26.88 / 33.95 | 26.68 / 33.77 | 27.40 / 34.12 | +1.92% / +0.50% | 1625.55 / 1619.68 |

B 对同源重编 A′ 的文本读分别快 1.80% 和 2.71%。64 KiB 二进制镜像的原生读写约为补丁 Wasm 的 **46.4 / 47.0 倍**。表中两项 64 KiB 共用相同原生对照样本。

20 KiB 文本读 / 写的 `DAP_JTAG_Sequence` 往返分别从 311 / 331 降到 287 / 323，64 KiB 从 993 / 1057 降到 903 / 1027。64 KiB 镜像读 / 写仍为 904 / 1027。实际 JTAG 在途请求深度始终为 1，当前 HPM 链路走同步 JTAG 序列；旧补丁提高的是 CMSIS-DAP SWD 块队列的容量。本板能观察到的收益来自文本缓冲扩大，旧 F103 SWD 的收益需在相应硬件上独立验证。

最终 SRAM 含保护区逐字节恢复，应用心跳继续增长，目标时钟配置一致，探针保持正式配对、25 MHz、idle 8 且所有观察引擎空闲。仅退出本任务硬件服务。候选 Wasm、JS 和构建材料留在工程外临时目录，SRAM 备份在恢复确认后删除。
