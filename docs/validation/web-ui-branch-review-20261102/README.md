## 发现

### F1 / P1：显式沿用目标没有推进本页 previous，切回旧目标不清固件

位置：候选 web/app/ui/session-context.js:47-65、124-130。
步骤：初始烧录页F103；RTT选择H743形成会话目标；烧录页点击沿用目标并载入H743固件；手动把烧录目标切回F103。
applyTarget 修改选择器却不更新事件闭包 previous；previous 仍为初始F103，change判定目标没有变化，跳过 invalidate。flash.file 继续保存H743文件。新的目标与旧固件因此可同时进入烧录流程；本轮未执行烧录，不声称已造成Flash损坏。
修正方向：每页真实目标状态独立保存；显式沿用和手动切换共用一个状态转移函数，并在成功应用后推进previous。覆盖A→沿用B→手选A及连续多次沿用。

### F2 / P1：ARM调试/波形把全局会话目标当作本地已采用目标

位置：候选 web/app/ui/session-context.js:12、18-20、29-31。
步骤：波形载入F103 ELF并选择变量；在RTT切成H743；回到波形。
generic('arm')直接返回最新context.target；sameTarget对scope只比较架构，对ARM调试也跳过具体板型。于是会话目标显示H743，沿用按钮被禁用为“已一致”，但波形的F103 ELF和变量地址没有失效。调试页同样存在此身份判定路径。这里不是要求任意跨页选择都强制清空各页，而是每页必须保留其实际采用的目标，允许明确沿用时再清空。
修正方向：本地目标绑定不能随全局context读取动态漂移。分别记录页内targetId及ELF归属，在未沿用时显示差异；不能用同为ARM推断板型相同。

## 距离商业软件

定位：功能丰富的工程试用版，已有可商用子路径与较好的证据记录；尚不足以认定为陌生客户独立使用的通用正式版。视觉层面接近专业工程工具，可靠状态、恢复和支持边界比继续美化更重要。不用未经用户测试的百分比或固定周数冒充成熟度量化。

1. 合并门槛：修复上述两个状态缺陷，补UI事件组合验收；冻结产物与最终源字节绑定。
2. 限定范围试用门槛：明确支持板型/固件/频率/操作矩阵；对选固件→烧录→调试→RTT/波形→停止恢复执行真实E2E，并覆盖USB拔插、页面刷新、服务重启和操作失败后的恢复。已有ZL-002/003/004/098需要按承诺范围分级解决或明确排除；本轮没有重新复现这些历史问题。
3. 正式销售门槛：干净Windows环境安装/升级/回滚及数据保留验收，首次使用无需作者指导；可导出诊断包、清楚的版本与兼容矩阵、长期稳定性和支持流程。安装签名/第三方许可证等尚未审计，不能直接认定缺失。
4. 性能：ZL-093记录的HPM同条件Web烧录21.905s对OpenOCD2.971s、ZL-006大记录端到端等待仍影响用户感知；均为历史报告范围，并非新分支计时。优先优化真实等待及取消/阶段反馈，不能以UI改版宣称性能改善。

限定少数已验证板型并提供工程师支持，可以先做受控试用；承诺广泛板型、稳定即插即用和客户自助排错，则还需要完整产品化验收周期，不能按“还差一次UI美化”估算。
