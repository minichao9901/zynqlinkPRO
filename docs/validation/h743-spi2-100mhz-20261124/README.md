# H743 → J7 SPI 从机 100 MHz 复查

2026-11-24，沿用已验收的 SPI 接线、H743 夹具修订 3 和由 HS3 临时加载的 RAW4 ABI 2。J7 序列号 `12345678`，H743 CDC 序列号 `H743SPI0001`。H743 PLL2／SPI2 分频报告 100 MHz，未外部测频。每点发送 4×4,096 B，由 J7 EP10 收取并逐字节核对。

## MOSI 延迟扫参

GPIO 速度 3、2、1 的四模式和速度 0 的 Mode 0、1，分别扫 MOSI tap 0–31。448 个完整点均未通过。速度 1–3 的组内最小成帧数仍在数千量级。速度 0 虽可使成帧计数降至 0 或 1，J7 接收到的字节接近零，不能进入长测。该实验只调 MOSI，SCK/NSS 共用的输入 delay 保持原值。具体物理波形仍待捕获。 [448 点](mosi-delay-sweep.json)

## 连接状态

扫描途中 J7 WinUSB 报 `Pipe error`，随后 Windows 未枚举到 J7 和 HS3，速度 0 的 Mode 2、3 未扫。H743 COM52 仍响应，停止命令成功、GPIO 速度恢复到 3。HS3 的 Microsoft 签名 FTDI `oem6.inf` 仍在，重新应用并扫描后没有设备可绑定，XSCT 无目标。USB 断开原因待确认，后续板测及四模式 100 MHz 长窗待恢复连接。

## 三线采样候选

诊断 bitstream 增加一次性旁路采样，首次片选且检测到时钟活动后记录 1,024 组。每组 12 位按 `{NSS[3:0], SCK[3:0], MOSI[3:0]}` 打包，最低槽最早。报告统计 NSS 高电平槽和 SCK 半周期采样长度，用于区分片选假边沿与时钟假边沿。测试验证了 100 MHz 的正常输入、重触发和 AXI 读回，再由主机解析合成样本。

完整 Vivado 2018.3 构建通过，133.333 MHz 约束下 setup／hold 裕量 **+0.051／+0.053 ns**。此配对为诊断候选，等待 HS3 枚举后上板。四模式稳定性须通过逐字节短测和长窗确认。 [离线证据](offline-diagnostic.txt) · [配对](../../../prebuilt/selectio-spi-pad-diag-20261124/README.md)

## 探针恢复后的三线采样

经 HS3 临时加载诊断配对，物理 OCM 对拍 80,668 B。H743 单次片选发送 4,096 B，前 4,096 个输入采样槽中，Mode 0–3 的 NSS 分别出现 64／104／111／69 个高槽，脉冲宽度为 1–2 槽。同时，SCK 只看到 1,624／1,639／1,637／1,607 次变化，理想约为 2,047 次。用对应固定槽和位偏移重放各模式时，MOSI 的对齐样本可完整匹配源载荷。由此定位到输入采样已出现假片选和缺时钟，具体电气根因待确认。

SCK/NSS 共用 tap 取 0–30 的偶数档，MOSI tap 取 0/12/24，配合 GPIO 速度 1–3 和四模式，共 576 个点，零通过，delay 已回读恢复。H743 修订 4 增加分线驱动及固定码型，已编译，等待经 DFU 加载后继续。 [原始采样](pad-captures/summary.json) · [联合扫参](group-delays.json)

## 修订 4 固定码型与分线驱动

修订 4 经 USB DFU 写入 40,288 B 并全量读回一致。恢复 BOOT0、从 Flash 启动后，以同一诊断配对完成 64 组 SCK／MOSI／NSS 输出速度、四种模式共 256 点。零通过。MOSI 速度取 0 后，四模式最佳各收 16,347／16,372／16,377／16,349 B（发出 16,384 B），仍有 3–4 次成帧错误，首字节已和载荷不符。每点仍为 4×4,096 B 对拍，测试后恢复 H743 输出速度和码型。

保持三线输出速度 3，用相同布线发送固定码型。Mode 0、1 下，全 `00` 和全 `FF` 都收全 4,096 B，成帧计数为零。4,096 槽中约 2,048 个 SCK 边沿，NSS 无高槽。改成全 `55` 后分别只看见 1,025／1,026 个 SCK 边沿，Mode 1 同时出现 244 个单槽 NSS 窄高脉冲。异常与 MOSI 跳变有关，电气串扰及反射仍需模拟波形佐证。数字滤波可以排除短暂假片选或重复时钟边沿，原始采样里完全消失的边沿还需提高采样率或改善输入裕量。 [DFU](r4-dfu.json) · [256 点](r4-edges.json) · [固定码型原始记录](r4-fixed-patterns/)

Mode 1 的固定 `00` 额外跑了连续 3 秒。J7 收到 37,493,484 B，持续吞吐 12.46 MB/s，零待收、零丢弃、零成帧；H743 DMA 比 J7 实收多 16 B，在发送 FIFO 尾差判据之内，确认传输链在 100 MHz 下有能力搬运接近满速的连续数据。

用分线低 MOSI 速度的组内最佳设置重抓四模式，SCK 变化次数恢复到 2,043–2,048，NSS 高槽为零。用相同码型的 1,018 位逐相对齐，固定 400 MS/s 槽最优仍各有 206／180／181／203 个差异。分线降速改善了时钟和片选采样，但在本接线下也缩小了数据线的采样裕量。 [固定码型持续速率](r4-constant-throughput.json) · [低 MOSI 速度采样](r4-low-data/)

## 未滤波速度对照

沿用诊断配对和修订 4，11 组三线速度、25/50/12.5 MHz 与四模式共 132 个逐字节短测。MOSI 速度 0 配合 SCK 速度 1–3，可以让四模式均通过 25 MHz。50 MHz 短测通过项来自 Mode 1、2。用 SCK／MOSI／NSS 速度 `3/0/1`，四模式在 25 MHz 各连续 3 秒，合计 37,490,584 B 全量匹配，零待收、零丢弃、零成帧。完成后回读恢复分线速度、码型和输入 tap。 [132 点对照](r4-rate-reference.json) · [25 MHz 连续窗口](r4-common25-window.json)

同设置把原先较弱的 Mode 0、3 各延长到 60 秒。分别实收 187,499,829 B 和 187,499,444 B，持续吞吐约 3.124 MB/s，两轮均无错字节、无待收、无丢弃、无成帧。串口首次设置曾被 Windows 以 995 中止，按同一 USB 序列号重新打开后正常。 [两轮 60 秒](r4-25mhz-modes03-60s.json)


## J7 接收滤波实板复查

实验 bit 以 800 MS/s 采集 SCK、MOSI。NSS 继续由 400 MS/s 的 SWDIO 接收器采集，扩成八槽时间网格来判定片选边界。去选需连续五槽为高，同极性采样边沿之间至少隔五槽。注入 1.7 ns 的 SCK 重复边沿脉冲及 3.5 ns 的 NSS 假高，四模式、八个相位、50/72.727/100 MHz 合计 9,424 B 对拍通过。133.333 MHz 布线后 setup／hold 裕量 +0.209／+0.029 ns。经 HS3 临时加载，物理 OCM 核对 80,668 B，FCLK 读回 133,333,332 Hz。 [离线结果](filter-offline.txt) · [配对](../../../prebuilt/selectio-spi-pad-filter-20261124/README.md) · [加载证明](filter-load.json)

## 剩余错误与 50 MHz 去选门限

用 800 MS/s 重放同一 100 MHz 短采样。三线速度 3 时，四模式的 MOSI 各对齐 1,016 位均匹配，SCK 缺失如上。将三线速度改为 `3/0/1` 后，SCK 变为 2,046–2,047 次，NSS 窄高为零，但四模式最佳固定槽各有 202／180／180／203 个 MOSI 位不匹配。这两组对照覆盖相同的源载荷和现有线束。 [800 MS/s 低 MOSI 速度](filter-wide-input-low-drive/)

在 50 MHz、SCK/NSS 速度 3、MOSI 速度 1 或 3 时，所抓窗口 SCK 为 1,024 次变化，与完整时钟相符。Mode 0、3 有少量 NSS 假高长达 6 个逻辑槽，对应约 7.5 ns。第一版五槽门限会把这些高脉冲当成去选。新版将 50 MHz 及以下的门限升至 13 个逻辑槽，保留高档五槽门限。 [50 MHz 三线原始采样](filter-wide-input-50mhz/)

第一版 50 MHz、三线速度 3 下，Mode 1 的 60 秒实收 374,998,591 B，完全匹配。Mode 2 三轮 60 秒中一轮完整通过，另两轮分别报告 483,950、566,881 个环形接收丢弃字节。后者成帧计数为零，PC 最长 USB 读回等待 36.57 ms，复跑通过的最长等待为 5.01 ms。报告保留失败轮，环满的具体触发环节仍待确定。 [首轮长测](filter-v1-50mhz-60s.json) · [Mode 2 两次复跑](filter-v1-50mhz-mode2-repeat.json)
