# H743 → J7 SPI 从机 100 MHz 复查

2026-11-24，沿用已验收的 SPI 接线、H743 夹具修订 3 和由 HS3 临时加载的 RAW4 ABI 2。J7 序列号 `12345678`，H743 CDC 序列号 `H743SPI0001`。H743 PLL2／SPI2 分频报告 100 MHz，未外部测频。每点发送 4×4,096 B，由 J7 EP10 收取并逐字节核对。

## MOSI 延迟扫参

GPIO 速度 3、2、1 的四模式和速度 0 的 Mode 0、1，分别扫 MOSI tap 0–31。448 个完整点均未通过。速度 1–3 的组内最小成帧数仍在数千量级。速度 0 虽可使成帧计数降至 0 或 1，J7 接收到的字节接近零，不能进入长测。该实验只调 MOSI，SCK/NSS 共用的输入 delay 保持原值。具体物理波形仍待捕获。 [448 点](mosi-delay-sweep.json)

## 连接状态

扫描途中 J7 WinUSB 报 `Pipe error`，随后 Windows 未枚举到 J7 和 HS3，速度 0 的 Mode 2、3 未扫。H743 COM52 仍响应，停止命令成功、GPIO 速度恢复到 3。HS3 的 Microsoft 签名 FTDI `oem6.inf` 仍在，重新应用并扫描后没有设备可绑定，XSCT 无目标。USB 断开原因待确认，后续板测及四模式 100 MHz 长窗待恢复连接。

## 三线采样候选

诊断 bitstream 增加一次性旁路采样，首次片选且检测到时钟活动后记录 1,024 组。每组 12 位按 `{NSS[3:0], SCK[3:0], MOSI[3:0]}` 打包，最低槽最早。报告统计 NSS 高电平槽和 SCK 半周期采样长度，用于区分片选假边沿与时钟假边沿。测试验证了 100 MHz 的正常输入、重触发和 AXI 读回，再由主机解析合成样本。

完整 Vivado 2018.3 构建通过，133.333 MHz 约束下 setup／hold 裕量 **+0.051／+0.053 ns**。此配对为诊断候选，等待 HS3 枚举后上板。四模式稳定性须通过逐字节短测和长窗确认。 [离线证据](offline-diagnostic.txt) · [配对](../../../prebuilt/selectio-spi-pad-diag-20261124/README.md)

## 探针恢复后的三线采样

经 HS3 临时加载诊断配对，物理 OCM 对拍 80,668 B。H743 单次片选发送 4,096 B，前 4,096 个输入采样槽中，Mode 0–3 的 NSS 分别出现 64／104／111／69 个高槽，脉冲宽度为 1–2 槽。同时，SCK 只看到 1,624／1,639／1,637／1,607 次变化，理想约为 2,047 次。用对应固定槽和位偏移重放各模式时，MOSI 的对齐样本可完整匹配源载荷。由此定位到输入采样已出现假片选和缺时钟，具体电气根因待确认。

SCK/NSS 共用 tap 取 0–30 的偶数档，MOSI tap 取 0/12/24，配合 GPIO 速度 1–3 和四模式，共 576 个点，零通过，delay 已回读恢复。H743 修订 4 增加分线驱动及固定码型，已编译，等待经 DFU 加载后继续。 [原始采样](pad-captures/summary.json) · [联合扫参](group-delays.json)
