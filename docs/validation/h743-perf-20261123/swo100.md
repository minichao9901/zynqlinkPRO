# H743 400/200 MHz 的 SWO 两种 100 档

H743 上的 RAM 目标程序验证 CPU400/HCLK200 后运行，保持现有标准排线。探针参考分频 N=32，原 CDC OUT 防护融合配对。两个数值分别为 **100 Mbaud NRZ** 与 **100 Mbit/s Manchester**，后者是 200 Mchip/s。 [硬件记录](swo100-evidence.json)

| 接收路径及码型 | 本轮结果 | 验收范围 |
|---|---|---|
| M15 带负载的本端 NRZ 混合码 | 60 秒会话，3,378,984 B 全匹配，零帧错和尾差 | J7 发码与回采，帧间有空档 |
| M15 带负载的本端 Manchester 混合码 | 60 秒会话，17,696 B 全匹配 | J7 发码与回采，帧间有空档 |
| L14 的 H743 TAP 回送 NRZ 混合码 | 3 秒短窗 2,784 B 通过。初始长窗在约 3.92 秒报 2 个帧错，已验 3,456 B。tap4 复测在约 22.49 秒报 3 个帧错，已验 19,872 B | L14 突发解码已证明，稳定 60 秒验收未通过 |
| L14 的 H743 TAP 回送 Manchester 交替码 | 60 秒会话，18,048 B 全匹配 | L14 的 100 Mbit/s 交替码突发 |
| L14 的 H743 TAP 回送 Manchester 混合码 | 128 个组合均未通过。对原始样本作定相比较，交替码可对齐到零差，混合码最佳点仍有 301/568 个码元不符 | 采到的回送波形已经偏离已知码流，从本组无法确认接收端上限 |
| H743 原生 ITM→SWO | 复电后 DBGMCU 恢复。第一次经系统总线初始化 2 Mbaud 对照时 AP 失去响应，未执行原生 100 档 | 待恢复后改用 AP2 验证源端寄存器 |

以上 60 秒为反复提交短帧的会话时长。源端连续出数和 L14 混合码的完整长窗尚未验收。

## 现场

前面的波形测试结束后目标和探针已经恢复。用户随后整套断电，J7 JTAG/RAM 临时加载原融合配对，物理 OCM 又对拍 80,260 B。H743 接入后用 SWD/JTAG 均能读到 DBGMCU，AP2 也能读回设备 ID。原生配置途中的异常后，清理和外层恢复未完成，AP0 在 SWD 下仍不可访问，JTAG TAP 回读为零。准备在恢复上电后只经 AP2 单步核对 SWO 寄存器。STM32 目标 Flash、探针 QSPI 及排线未修改。 [ST RM0433 DBGMCU 与复位行为](https://www.st.com/resource/en/reference_manual/rm0433-stm32h742-stm32h743753-and-stm32h750-value-line-advanced-armbased-32bit-mcus-stmicroelectronics.pdf)
