## 边界、失败与改进

* 旧IO-only策略在61～66.667MHz请求实际最高64.286MHz；不是时序失败。新PS只在显式RISC-V最高档选择现有ARM PLL/10，其他请求仍IO PLL；没有写任何探针PLL、CPU/DDR分频或目标MCU PLL。时钟来自SRCSEL/PLL/分频寄存器计算，不是外部频率计测量。
* 64.286MHz的idle20失败、21通过；66.667MHz的20/21失败、22通过，仍符合约0.33us的DTM等待量级。mode16/17均通过。更大idle会减速，参见[R20](../hpm6800-idle-frontier-20261102/README.md)。本轮到达当前133MHz实现下半速TCK档，没有在未验证的更高FCLK继续上探。
* 高频识别与数据通路分开：34.615MHz mode0的公开IDCODE读错，三个窗口均保留失败/恢复；mode17在30～66.667MHz公开识别和随机读写通过。不是把识别坏点静默删除或拿低速识别冒充高频连接验证。
* ZL-085：流时钟原硬编码60MHz，与DAP构建cap不一致，已统一。最高档选择保留DDR所有权守卫；生产C模型覆盖60/66 cap及占用时拒绝改钟。首次构建暴露133 helper被旧fixed宏隔离，已修正、重新链接，失败日志保留。
* ZL-004：首次ARM档PS候选OCM匹配却停_exit/USB缺失，尚未测速。保留PC/物理寄存器及该ELF。新增经cache flush发布的probe_boot_diagnostic启动阶段/返回码，不绕过自检；新配对正常启动不代表偶发故障已修复。
* ZL-070：前轮60MHz的250k三轮有坏点保留。本轮66.667MHz的上述窗口通过不证明任意时长或所有板卡的绝对上限。
* ZL-080的2us极端过载短包问题未因这些成功点而关闭。本轮提高了可保持周期的采样率，没有取消真实gap检查。
