## 五路两点滤波下的逐线校准

沿用同一 20-pin 灰排线、CPU/HCLK 200 MHz、SWD 约 10 MHz 和临时 SRAM 分支负载。先测公共数据和时钟的 5×5 tap 网格，再独立搜索 CLK、D0、D1、D2、D3。每路均有独立的 0–31 tap 装载和确认。先以 4 tap 步进粗扫，再验证选中的中心及其邻域。记录顺序为 D0/D1/D2/D3/CLK。候选按采集诊断、原生解码和预期分支序列筛选。单个末包在采集结束处截断的情况单独记录，1 秒严格通过判定仍计入该项。[IDELAYE2 装载说明](https://docs.amd.com/api/khub/documents/IbGcnPFe6eF19RHma_Y~IA/content)

## 滤波实板对照

RAW4 用 200 MHz 时钟采样五路输入。原版在连续两个样本一致时更新状态，样本不一致时保持上次状态。使用与正式 bit 匹配的已布线 DCP，在临时副本修改滤波 LUT 的 INIT。旁路时 LUT 直通上一拍输入，保留采样寄存器和布线。只保留时钟滤波时，D0–D3 的 LUT 从 `8'hE8` 改为直通 I0 的 `8'hAA`。全旁路另将 CLK LUT 改为直通 I1 的 `8'hCC`。两份试验 bit 的 setup/hold 余量均为 0.067/0.044 ns，布线错误均为 0，配置载荷相对原版分别有 28/32 字节差异。三种 bit 使用同一正式 PS ELF。[RAW4 实现](../../../fpga/rtl/orbtrace_parallel.v) · [AMD LUT3 INIT 说明](https://docs.amd.com/r/2024.1-English/ug953-vivado-7series-libraries/LUT3)

| 滤波设置 | 25 MHz 零 tap | 28.57 MHz 各自重新寻优后的 100 ms |
| --- | --- | --- |
| CLK 和四路数据均两点滤波 | 100 ms 三轮成帧错误为 0，历史 1 秒三轮完整通过 | 0 个成帧和包错误，tap 为 12/18/6/4/16 |
| 仅 CLK 两点滤波 | 50 ms 成帧错误为 0，解复用读出保留源 ID 127 | 487 个成帧错误，tap 为 31/28/24/24/16 |
| CLK 和四路数据均旁路 | 50 ms 有 47 个成帧错误 | 3687 个成帧错误，tap 为 20/0/20/16/20 |

28.57 MHz 也以同一组 12/18/6/4/16 tap 做了 1 秒交替对照。仅 CLK 滤波的三轮成帧错误为 7、4765、4775，全旁路为 36977、36879、812。20 MHz 零 tap 的仅 CLK 滤波组同样读出了源 ID 127。完整链路判定需要同时检查采集、解复用和解码结果。

## 收尾

两份试验 bit 通过 JTAG/RAM 临时加载。最终恢复正式 bit 和 PS ELF，以物理 MEM-AP0 复核 85,844 字节运行代码。FCLK 为 119,999,998 Hz，SWCLK 约 10 MHz，TRACECLK 由 PLL1 R 分频读回推算。五路回到 0 tap。H743 恢复原 20 MHz 分频、512 字节 SRAM、20 个核心寄存器和调试配置，继续运行。整片 2 MiB Flash 哈希、三页 SDRAM 抽样哈希、RCC 和本轮管理的 CoreSight/GPIO 均核对一致。最终采集、DDR、CDMA、RTT 和 HSS 空闲，既有工作台与共享硬件服务保持在线。[恢复证据](evidence.json)

脚本、临时 bit、DCP、备份和采集产物均在系统临时目录中处理。5,734 个文件已移入回收站，原临时路径已核对清空，本任务进程均已退出。ZL-063 继续记录高频错误。
