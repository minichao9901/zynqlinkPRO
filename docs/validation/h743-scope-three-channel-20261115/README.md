# H743 三变量 5 µs 采样中断与历史对照

2026-11-15（上海时间），ZL-255。用户报告 v1.3.11 本机工作台的一次采样中断。先通过同一工作台的 `page scope describe`、`summary` 和 `rateAdvice` 只读取证，随后用同板、同三个变量和同一固定 EXE 复测 10 µs 和 5 µs。

页面载入 `fw.elf`，SHA-256 `a4bceb12d5ac54c7f1eb254b31144d84708f16a62cacda96264f160c9d4dd3b6`，与本机 SuperLinkPRO 的 H743 Scope 示例 ELF 一致。此证据核对了上传文件，未另行读取板上 Flash。请求 SWD 50 MHz、5 µs（24 MHz 时基下 120 ticks）、5 s，实际路径为本机 USB 代理 EP87。页面回显 SWD 49 MHz，未另取实际链路寄存器。开关回报 `0xa0`，包含短批次和暂停串口桥。

变量为 `g_pack.f_sin:f32@0x24001014`、`g_pack.u_ramp:u16@0x24001020` 和 `g_pack.i_sq1k:i16@0x24001022`。每组有效载荷 8 B，变量分布在两个不相邻的对齐字。网页模型估读约 8.63 µs/组，保守建议为 11 µs；这两个值是模型结果。本轮报「本机 HSS 接收队列溢出」，浏览器已收 0 字节、0 包，尚未收到 DEF，`probeMetrics=null`。缺少探针生产数、跳拍和 USB 成帧数据，无法给此次采集计算实得率或定位队列为何塞满。

## 同一块 H743 的实测

测试在同一个 `127.0.0.1:8882` 固定 EXE 工作台进行。J7 探针 USB 序列号 `12345678`，抓取 Windows USBPcap bus 3、device 8、EP `0x87`。各轮都请求 SWD 50 MHz 和 5 s，DEF 实际回报 SWD `49,999,999 Hz`，探针时基 24 MHz，线上的三个变量地址、尺寸和标量类型与页面一致。探针停止后的物理 MEM-AP0 比对确认 OCM 85,844 B 与 `prebuilt/release-20261106/application.elf` 一致，`BOOT_MODE=0`。探针空闲 FCLK 读回 119,999,998 Hz。SWD 取自采集 DEF，空闲 FCLK 来自寄存器读回。

| 周期 | 实际组/s | 探针跳拍数（占比） | USB DATA 帧及组数 | USB MB/s | 主机队列峰值 | 网页组数 / 线上组数 |
|---|---:|---:|---|---:|---:|---:|
| 10 µs / 240 ticks | 99,999.80 | 1（0.000199%） | 8,089 帧，8,087 帧为 62 组 | 0.827 | 26 KiB | 501,446 / 501,446 |
| 5 µs / 120 ticks，第 1 轮 | 41,422.49 | 189,473（79.289%） | 49,492 帧，全部 1 组 | 20.825 | 15.9375 MiB | 16,383 / 49,492 |
| 5 µs / 120 ticks，第 2 轮 | 41,572.99 | 185,966（79.214%） | 48,799 帧，全部 1 组 | 20.876 | 16 MiB | 15,615 / 48,799 |
| 5 µs / 120 ticks，第 3 轮 | 41,414.46 | 189,165（79.293%） | 49,400 帧，全部 1 组 | 20.841 | 16 MiB | 16,255 / 49,400 |

实际组速按 USB DATA 首末时间戳（含末帧组数）计算。10 µs 的时间轴为 5.01447 s，5 µs 的三轮在 1.174–1.195 s 样本窗口后中断。跳拍比例按探针 `skipped / (skipped + produced)`，USB 吞吐按有效 URB 载荷字节和首末载荷完成时间计算，含携带部分有效数据的取消完成。四轮探针生产数、USB 字节计数和帧计数均与 USBPcap 对账一致，USB HSS 序号连续，探针 SWD 读错误及 USB 错误均为 0。10 µs 正常 STOP，网页对账一致；5 µs 三轮网页均报队列溢出。第 1 轮峰值是网页最后一次成功读取所回报的队列水位，错误响应不附水位。

5 µs 每组只有 8 B 有效值，却占一个完整的 512 B HSS 帧。三轮约 99.95% 的相邻 DATA 帧之间有采样时标缺口。探针采样逻辑在赶不上调度时间时记跳拍，PL 成帧逻辑发现相邻时标差不等于设置周期就结束当前帧。两处 RTL 哈希与 RAM 配对的 `rtl-inputs.json` 一致。5 µs 的 USB 字节率因此约为 10 µs 的 25 倍，写入主机队列的速度超过当前网页 USB 代理交付速度。该次采集没有进一步拆分 SWD 事务、调度及背压各自造成的 deadline 开销。[采样调度](../../../fpga/rtl/probe_sample_engine.v#L220) · [时标与成帧](../../../fpga/rtl/probe_stream_engine.v#L198)

四轮的第一帧均为 `DEF(seq=0)`。在 5 µs 三轮中，DEF 从点击开始到 Windows USB 捕获的时间为 28–52 ms，网页也都收到 DEF。原截图的零包现场在复测前已经做过全局复位，缺少该次 USB 和接收时序。用第一轮 **实际 EP87 的 25,340,416 B** 按原 URB 大小离线回放到现用 `HssReceiver`，将首次消费者读取延迟到超过容量。接收队列到达 16,777,216 B 后清空，首次读取抛出同一溢出异常，交付 0 B。这个顺序会丢掉仍在队列中的 DEF，USB 代理也会给网页返回空数据和溢出状态。离线复现了零字节的路径，原截图当时首次读取延迟仍无现场时序可核对。[接收队列](../../../etm-service/tools/native_hss.py#L34) · [USB 代理错误响应](../../../etm-service/tools/native_probe.py#L457)

采集结束后已释放 USB/HID，恢复测试前的页面采样设置（6 µs、60 MHz、5 s）；HSS、DDR 和 DMA 回读空闲。操作未加载或重置目标/探针固件，未写目标 Flash 或 QSPI。[实测数据索引](evidence.json)收录各轮计数和校验信息。本机原始抓包、计数、网页时间序列和受控回放在 `build/h743-three-var-scope-20261115/`。
