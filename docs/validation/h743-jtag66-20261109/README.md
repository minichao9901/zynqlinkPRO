## 条件与机制

沿用正式 J7 bitstream 及其 7.5 ns 路由时序报告，setup/hold 余量分别 0.067/0.044 ns。PS 在独立目录构建，只为精确 66,666,666 Hz JTAG 请求开放 ARM PLL /10 路径。实际 FCLK 133,333,332 Hz，TCK 66,666,666 Hz，JTAG 模式 16。60 MHz 对照为 IO PLL、FCLK 119,999,998 Hz、TCK 59,999,999 Hz、模式 17。时钟来自读回寄存器与分频。RTT 窗口内用物理 MEM-AP0 确认时钟来源及 idle。先以 JTAG 10 MHz 建立连接，发送 TransferConfigure 设置并用 0x8d 确认 idle，再发送精确 Hz 的 SWJ_Clock 请求并重新读 IDCODE，核对校准后实际 TCK。

SRAM 与前次用相同 AXI 0x24050000 地址，512 words、depth32、每方向 64 块。计时使用 1 KiB TAR 回绕，两个不同的写入图案交替，读回验证相邻 3 KiB 未被改写。RTT 使用 8192 B 环和 1024 B 块。idle=3 时读扫描段数从 idle=1 的约 2.02/字降至约 1.02/字，支持短 idle 引发重扫。逐拍 ACK 归因仍待验证。

本轮刷新的是仓库已测 H743 ARM JTAG 记录。历史 F103ZE 的 SWD 66.666 MHz 成绩采用不同目标与协议，见 [1d9e642 的报告](../performance-limits-20261101/README.md#固定-fclk133-的极限-swd)。

## 恢复

两个 Zynq PS 配对均通过物理 MEM-AP0 执行段核对。最终重新 RAM 加载正式探针配对，恢复 SWD10、idle=1。H743 临时写入的 bank1 sector0 已从备份恢复。完整 2 MiB Flash 和 64 KiB 烧录工作区均独立读回与原内容一致。目标回到 CPU/HCLK60、TRACECLK20，运行态，CDC 回显正确。捕获、DDR、DMA、RTT 和 HSS 均空闲。配对及逐轮证据见 [实验配对](../../../prebuilt/h743-jtag66-20261109/manifest.json) 和 [evidence.json](evidence.json)。
