# H743 SRAM 与 RTT 吞吐差异定位

2026-11-23，J7 `12345678` 与同一块 H743 历史 CDC。目标使用 Flash 中已核对的 CDC ELF，保持 CPU/HCLK 60 MHz。两套探针配对都由 HS3 临时加载，并核对 OCM。SWCLK/TCK 为寄存器换算的 99,999,998 Hz。下列 MB/s 均为十进制。

## 1. SRAM 慢在哪里

同一块 H743、同一套 RAW4 + ABI 2、SWD tap8/slot25/idle4。每次跨 1 KiB 页传输 4,032 B，主机深度 4。读核对全量载荷，写在窗口后独立回读最终载荷和保护字。

| 工况 | 读 MB/s | 写 MB/s | 证据 |
|---|---:|---:|---|
| 停核，AXI SRAM | 4.93 | 4.72 | PL 队列约占主机窗口 94%／91%，队列以外探针处理约占 3% |
| 停核，DTCM | 6.67 | 5.33 | 同频、tap、slot、idle、事务长度和深度，仅换 SRAM 区 |
| 停核，AXI SRAM，主机深度 1 | 3.91 | 3.73 | 深度 4 已显著减少 USB 往返空隙 |
| AXI SRAM，CPU 在 Flash 执行单条自跳转 | 0.797 | 0.780 | PL 队列约占窗口 99%／98%，目标不执行数据访存 |
| EP6，探针 DDR 模拟同一原生块协议 | 13.67 | 13.30 | 目标 MEM-AP 从此对照路径移除 |

地址改为页对齐后，AXI SRAM 停核只改善到 4.97／4.76 MB/s。SWD idle4 改为 idle1 后，读升至 5.06 MB/s，写降至 4.53 MB/s。这些变化小于换 SRAM 区和运行状态造成的差异。

### JTAG

100 MHz、idle65 时，融合 ARM 连续 DRW 扫描的稳态预算为 `43 + 65 = 108 TCK/word`，裸载荷预算约 3.704 MB/s。实测 60 秒读／写 3.392／3.320 MB/s，补测取得 3.395／3.323 MB/s。两个方向的差距与扫描预算同量级。F103 HCLK128 的 6.406／6.162 MB/s 历史成绩用 idle11，单字少了 54 个 TCK。

idle61 的短窗读约 3.52 MB/s，持续写发生 FAULT。idle65 在前一轮长窗和本轮另一组短窗通过，也有一组新短窗写出现 FAULT。两次均能恢复 SRAM、时钟和运行态。idle77 短测读／写约 3.079／3.012 MB/s，RTT 约 0.710 MB/s。持续写的重复性仍待确认。 [JTAG 帧长](../../../fpga/rtl/jtag200_arm_stream.v#L25) · [F103 历史同口径对照](../spi-cdc-20261123/jtag100-ab/README.md)

## 2. RTT 限制在 USB 前

| 同一组 H743 SWD100 测试 | 有效吞吐 |
|---|---:|
| 原目标生产者，运行态 RTT／EP7 | 0.754 MB/s |
| 目标改为每 64 B 批量发布，运行态 RTT／EP7 | 0.754 MB/s |
| 250 ms 内不发 EP7 取流请求，仅在末尾读取探针侧累计值 | 0.749 MB/s |
| 停核，预填 16 KiB 环，2 KiB 搬运，5 次平均 | 4.066 MB/s |
| CPU 运行 SRAM 自跳转，预填同一环，5 次平均 | 0.764 MB/s |
| CPU 运行 Flash 自跳转，预填同一环，5 次平均 | 0.764 MB/s |

孤立的目标生产者按 DWT 计数一次填满自己的环，SWD 用的 AXI SRAM 夹具可写入 6.49 MB/s，JTAG 用的 DTCM 夹具为 15.00 MB/s。运行态读取预填环仍掉速，说明加快写环或停止主机取流都解决不了这里的主要瓶颈。SWD50 的两种 RTT 搬运路径也分别约为 0.747／0.756 MB/s。

同地址 1 KiB SRAM 请求，SWD 队列每页有 256 个数据字。物理 MEM-AP0 读取探针 PL 状态寄存器确认，H743 运行 Flash 自跳转时 WAIT 重试从 **257 增至 5,377（读）**、从 **267 增至 5,472（写）**，约为停核时的 20 倍。分析范围已定位到目标运行时的 MEM-AP WAIT，H743 内部为何频繁返回 WAIT 仍需跨 HCLK 对照。

### 拆端点前后的同板对拍

旧 ABI 1 的原生块 SRAM 准入限于 `0x2000xxxx`。因此在相同 DTCM 地址、同一 HCLK60、同一 SWD100 profile、同样 4,032 B 跨页与深度 4、同样 8 KiB RTT 环和 2 KiB chunk 重跑。

| 探针配对 | 停核 SRAM 读／写 MB/s | 运行态 RTT MB/s |
|---|---:|---:|
| 旧融合 ABI 1，旧原生 IN EP4 | 6.67／5.34 | 0.773 |
| RAW4 融合 ABI 2，RTT 用 EP7 | 6.67／5.33 | 0.773 |

H743 先前 CPU480/HCLK240 的 6.508／6.722 MB/s SRAM 和 4.359 MB/s RTT 是标准 CMSIS-DAP 深度 32 与 RTT→CDC。它们是独立的已取证成绩。完整性能签收还需要把目标 HCLK 档与实际业务的 SRAM 区和运行状态同时对齐。 [H743 历史吞吐](../h743-perf-20261123/README.md)

## 收尾与复核

已收尾核对 H743 历史 CDC Flash 装载段、HCLK、实际运行状态、COM43 回显。探针恢复 RAW4 + ABI 2 RAM 配对，物理 OCM 核对和引擎空闲检查通过。试验不改 H743 PLL、Flash 或探针 QSPI。各点数据和临时夹具的恢复判据见 [证据](evidence.json)，本机详细运行日志与诊断驱动保存在 `build/h743-throughput-audit-20261123`。
