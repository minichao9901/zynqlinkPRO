# F103ZE ETM 过采样诊断与 LA 原始码流对照（2026-10-30）

## 结论

`E:\superlinkPRO\etm\records\capture-2d6da5829a8c4811b7c5ed2ca9e08cc3` 是同一份 `fw-ze.elf` 在逻辑分析仪上的已知正确记录，目标 ELF SHA-256 为 `63881ed9f6c1187d56924795ccad3f151a677aea0dfa201823fe44e0cb857522`。记录元数据为 HCLK 48 MHz、物理 TRACECLK 24 MHz，TPIU 原始流 240013 字节，参考解码无错误。

F103ZE 的 PE2～PE6 静态逐 pin 验收通过；补强两根地线后，原来的 IDDR/TRACECLK 同步采样仍在 27～44 字节内出现保留源 ID `0x7f`，重复采样的错误位置变化，说明不是固定的位线映射错误，也不是 USB 丢包。

同一硬件、同一目标 ELF 改用 200 MHz 参考时钟做双级同步、两点稳定边沿判定的诊断路径后，采集 9040 字节：phase-1 TPIU 严格解析通过，410 个 formatter frame、1660 个 ETM 字节，OpenCSD 解码返回 0，得到 1578 个指令范围；首个 16 字节 formatter frame 与 LA 参考首帧完全一致，逐位差异为 0。

因此，目标固件、接线、地线和 TPIU 软件解析链路已经被证明正确，当前失败点在原来的 TRACECLK 相关 IDDR 采样窗口。加地线没有消除问题，降低目标时钟只能降低风险，不能替代接收端的采样窗口修复。

## 资源与时序

过采样诊断配对的实现资源为 19244 LUT、28030 FF、12 个 BRAM Tile、1 个 DSP；相对当前 native32 基线 19228 LUT、27858 FF、10 个 BRAM Tile，增量约为 +16 LUT、+172 FF、+2 BRAM。构建脚本的可验证 FCLK 为 100 MHz，setup/hold 分别为 +0.413/+0.034 ns；120 MHz 的 post-route WNS 为 -0.136 ns，所以不能把 120 MHz 当作该诊断配对的工作点。

## 后续优化方案

1. 保留当前普通 IDDR 路径作为生产基线，保留已验收 bit/ELF，不把诊断 bit 标成默认 ETM 交付。
2. 将过采样前端从“原始 16 字节诊断输出”拆成正式接收模块：先在 200 MHz 域完成五根引脚的同步和边沿判定，再把恢复出的 DDR 字节流送入 TPIU formatter frame 组帧，最后复用现有 `orbtrace_tpiu_demux`。
3. 正式路径先按 24 MHz TRACECLK 验证，再逐步提高目标 TRACECLK；每个频点都要用 OpenCSD 做端到端验收，并记录 FCLK/TCK、bit/ELF SHA-256。
4. 资源优化优先从 16K 诊断 FIFO、重复的诊断状态寄存器和原始码流搬运路径下手；生产模式只保留必要的同步器、frame FIFO 和 TPIU demux，目标是回收新增 BRAM，同时维持当前 LUT 水平。
5. 如果实测仍受 EMI 影响，再在 TRACECLK/数据输入端加入可选 IOBUF 驱动强度、slew 和小串联阻值参数；滤波必须以不破坏 3 ns 级数据转换裕量为前提，不能用过大的 RC 直接钝化 TRACECLK。
