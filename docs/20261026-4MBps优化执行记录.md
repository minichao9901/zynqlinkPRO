# 4 MB/s @ 50 MHz 优化执行记录

## 冻结基线

开始提交：`3c01617`，分支 `codex/main-continuous-scheduler`。
固件配对：`f49bf49` 的 prebuilt bit/ELF；其SHA256仍见 prebuilt/SHA256SUMS。
测量明细：`measurements/20261026-raw-pyocd-budget.json`。
F103保持96MHz，无目标Flash编程；下列均为十进制MB/s。

| 50MHz SWCLK | 读 | 写 |
|---|---:|---:|
| RTL上限，idle=1，1022字 | 3.956 | 4.077 |
| raw，16条流水，3轮×1000包 | 3.796 | 3.859 |
| OpenOCD，20KiB，6会话×300轮 | 3.326 | 3.417 |
| pyOCD0.46.0，20KiB，6会话×100轮 | 1.692 | 3.037 |

## 验收目标和顺序

主目标：F103@96MHz、SWCLK50MHz，真实20KiB线性SRAM读/写均达到4MB/s。
至少10会话，完整数据、写完成和恢复校验。主机保持空闲，不能把缓存/入队速度当线速。
raw目标约4.15MB/s，为应用层留余量；512B响应另列，避免仅优化大包。
60MHz作为第二运行点回归，不靠提高SWCLK掩盖50MHz效率。

1. 重新复现idle=0失效，找出具体事务/边沿；先测试当前已修复RTL是否仍失败。
2. 缩短core完成到下一事务启动的间隙；命令/结果握手不允许越过ACK、奇偶校验或错误中止。
3. 在测量支持的前提下引入命令/响应双缓冲和轻量描述符队列，隐藏PS/CDMA/USB间隙。
4. 优化主机跨页流水；优先现有OpenOCD路径，pyOCD异步接口作为独立工作项。

每一有效节点commit；先mock/真实M0目标仿真，再上F103。保留保守回退和异常恢复。
不直接删除协议turnaround，不凭一次高值判定达标，不移除必要的写完成检查。
