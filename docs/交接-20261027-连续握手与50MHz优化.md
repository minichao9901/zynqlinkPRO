- 真实M0的idle0/1/2均通过packets/errors/recovery；串行mock独立覆盖FAULT、
  parity部分完成和WAIT不消费下一写字；native USB队列所有权/回绕/复位竞态回归通过。
- 新bit上50/60MHz混合Transfer各150个随机场景，包含7/8门槛、255操作和TAR交叉；
  另有1200条小混合命令、8个嵌套块边界，均通过。
- packet和batch各100次中途EP0恢复；分别73/38次快照确认复位前RTL忙，恢复后
  引擎空闲、复位次数递增、无恢复或USB提交错误，每轮重新SWJ连接。
- 3会话×6尺寸×100轮×16请求，共28,800条队列请求通过，覆盖short/ZLP/4096B响应。
- 发布ELF核验请求idle0/1/2实际为1/1/2，测试结束恢复idle1。最后一次20KiB读写恢复
  校验仍匹配上述原始SHA256，RCC不变。

## 本轮实现与限制

- core在当前事务ACK成功且奇偶校验正确后接下一笔，packet引擎消费独立完成结果，
  写数据预取只在真实成功后推进。WAIT重试原字，FAULT/parity中止；保留末尾RDBUFF。
- 合并读parity/turnaround收尾，以及ACK寄存采样与下一必需相位。没有删协议时钟沿。
  idle1下1022字：读96171/写96173个FCLK，50MHz仿真上限约4.251MB/s。
- 普通混合DAP_Transfer的相邻同请求写复用repeat-write编码，不跨读或请求变更。
- 两处SWDIO数据/方向高电平保持违规已修，但零空闲随机整块仍有既有失败证据。
  普通固件把idle0钳为1；只有`--experimental-zero-idle`允许试验，不作为发布配置。
- 主机0x7f打包试验虽将20KiB从10包降到6包，实测没有收益，已撤回代码，保留负结果。
- 早返回输入采样窗口未解决，真实M0的AHB FAULT注入仍有模型限制；不扩大通过范围。

## 构建和使用

当前bit的routed上限为FCLK120MHz，setup **+0.300ns**、hold **+0.050ns**，
bitgen/DRC成功。128.57MHz setup=-0.256ns，不支持该频点。固件明确限制SWCLK≤60MHz。
中断时增量实现曾在bitgen因partial antenna失败；fresh实现成功，没有忽略DRC。
脚本现要求bit不早于routed DCP，时序元数据只在bitgen成功后发布，避免旧产物误认。

收尾的一次普通构建复查仍被Vivado标记top synthesis需要refresh，因而触发重复实现；
该轮已于04:05主动停止，日志`build/resume_up_to_date_console.txt`的exit1不是发布版本
构建失败。发布版本来自03:51成功的`build/compact_ack.bit`，配对ELF为
`build/compact_ack_safe.elf`，已按固定哈希完成上述全部上板验收。没有遗留构建进程。

预编译bit/ELF及构建清单在`prebuilt`；只通过JTAG加载Zynq RAM：

```powershell
python tools/run_xsct.py tools/download_dap_fpga.tcl prebuilt/zynqlink_packet.elf prebuilt/zynqlink_packet.bit
```

测速复现（目标应已运行96MHz固件且保持halt，不使用reset halt）：

```powershell
python tools/benchmark_sram_optimized.py --tag repeat50 --speed 50000 --sessions 10 --loops 300 --clock-script none --no-reset --openocd-exe build/openocd_runtime/openocd.exe
python tools/benchmark_cmsis_sram.py --speed 50000 --sessions 10 --loops 100 --prefix-words 2 --output results/optimization/repeat50.json
python tools/raw.py --speed 50000 --words 1022 --loops 1000 --depths 16 --output results/optimization/repeat_raw50.json
```

恢复时关闭OpenOCD，运行`python tools/dap_transport_control.py recover`后再连接。
不自动重放已接受的目标写操作；stock OpenOCD不会自动调用这个恢复入口。

## 后续性能瓶颈

core在idle1下已接近47个SWCLK/字的协议预算。50MHz raw距仿真上限约4–6%，
线性访问还承担TAR、小命令、DMA与USB往返开销。继续达到真实双向4MB/s需要
隐藏这些跨包开销，或先可靠解决零空闲；本轮没有把跨包硬件描述符队列当作已完成。
历史长期2.1MB/s降速没有被证明全面复现或解决。
