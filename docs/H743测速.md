# STM32H743 目标测速

2026-10-25。目标换成 STM32H743（Cortex-M7 r1p1，DPIDR `0x6ba02477`），
AXI SRAM `0x24000000` 与 DTCM `0x20000000` 均可读写。DAP 固件为
`prebuilt/zynqlink_packet.*`（60 MHz 上限），OpenOCD 对比 nightly 与
4 行流水线补丁版。

## 480 MHz 固件（跑满 H743 上限）

烧录 `stm32h743_rtt_speed` 固件（PLL1: 25 MHz × 192/5 / 2 = **480 MHz**，
AXI/HCLK 240 MHz，CPU 480 MHz），回读 `g_sysclk_mhz = 0x1e0 = 480`、
`g_clk_err = 0` 确认时钟生效。CPU 运行在 RTT 循环里，测试时 `halt` 而不复位，
保证 PLL 保持；测区选 `0x24010000`（避开固件 bss 0x24000000..0x24003174）。

| 配置 | 读 MB/s | 写 MB/s |
|---|---:|---:|
| 64 MHz 目标（默认时钟），64 KiB @60 MHz | 4.05 | 3.96 |
| **480 MHz 目标，64 KiB @60 MHz** | **4.01** | 3.97 |
| 480 MHz 目标，64 KiB @64 MHz | 4.10 | 3.97 |

**结论：目标从 64 MHz 提到 480 MHz，速度没有变化**（4.05 → 4.01，噪声内）。
这直接排除了目标侧 WAIT/响应速度作为瓶颈——限制在 DAP 的 SWD 帧与 USB 往返。

## 结果（64 MHz 默认时钟目标，60 MHz SWCLK）

| 块大小 | OpenOCD | 读 MB/s | 写 MB/s |
|---|---|---:|---:|
| 20 KiB | nightly | 3.30 | 3.77 |
| 20 KiB | 补丁版 | 3.66 | 3.66 |
| 64 KiB | nightly | 3.56 | 3.97 |
| 64 KiB | **补丁版** | **4.05** | 3.96 |
| 128 KiB | 补丁版 | 4.12 | 3.96 |

- DTCM（0x20000000）与 AXI SRAM（0x24000000）结果一致（4.08/3.94），
  说明瓶颈不在目标内存类型。
- 64 MHz SWCLK：64 KiB 读 4.11 / 写 3.99，稳定；
  69/72/75/80 MHz 均连接失败（`Examination failed` / 写内存失败），
  480 MHz 目标下结论相同。
  FPGA 时序上限是 81.8 MHz，所以这是链路/采样相位限制，不是 FPGA 时序。

## 结论

1. **换快目标没有再打开新的上限**：60 MHz 下读约 4.1、写约 4.0 MB/s，
   与 F103 同一量级；目标 64 MHz → 480 MHz 也只有噪声级差异（4.05 → 4.01）。
   瓶颈是 SWD 帧 + USB 往返，不是目标主频。
2. 补丁版 OpenOCD 在 H7 上仍有 **+14% 读**（3.56 → 4.05），写持平。
3. 60 MHz、每字 46 个 SWCLK 的理论上限是 5.22 MB/s，实测 4.05 约为 **78%**；
   剩余 22% 是每个块的 USB 往返与命令处理。
4. 写比 F103（4.10）略低，且 DTCM/AXI 一致，怀疑是 H7 AHB-AP 写事务的
   固定开销，暂未继续拆解。
5. 69 MHz 失败与目标主频无关（480 MHz 目标同样失败），更像是 FPGA 侧
   分频/采样相位在该频点没有余量，需要按频点重新标定采样点。

## 复现

```powershell
python tools\benchmark_sram_optimized.py --tag h7_64k_60 `
    --speed 60000 --sessions 3 --loops 30 --address 0x24000000 --size 65536 `
    --clock-script none --config tools/openocd_h7.cfg `
    --openocd-exe <openocd-patched>\openocd.exe --scripts <openocd-patched>\scripts
```

`tools/benchmark_sram_optimized.py` 已支持 `--address/--size/--clock-script/--config`，
可直接对任意目标测速。
