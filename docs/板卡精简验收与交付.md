# 板卡精简验收与交付

完整工作台验收采用七组清单，每组五项，按优先级排列，另做三轮跨页压力测试。定向修复执行受影响的板卡、链路和条目，并在报告中列出实际范围。上板、写入、固化和发布按本次授权执行。

## 板卡与固定档位

| 目标板 | SRAM、烧录、调试、RTT Viewer、RTT 转发、J-Scope | ETM |
|---|---|---|
| STM32F103ZE | SWD 60 MHz、JTAG 60 MHz，各跑一遍。使用 CDC48 基线，JTAG 结束后恢复 AFIO/APB2 与目标状态。[SRAM、RTT 序号和高速采样实测](validation/performance-limits-20261101/README.md) | ETMv3，SWD 10 MHz，CPU/HCLK 48 MHz，TRACECLK 24 MHz。[实测](validation/release-20261106/README.md) |
| STM32H743 | SWD 50 MHz、JTAG 50 MHz，各跑一遍。吞吐使用 CPU480/HCLK240 配置并记录缓存状态。JTAG 50 MHz 有重复 SRAM、RTT 序号及 J-Scope 60 秒的证据。[实测](validation/h743-workbench-acceptance-20261109/README.md) | ETMv4，SWD 10 MHz，CPU/HCLK 60 MHz，TRACECLK 20 MHz。[实测](validation/h743-workbench-acceptance-20261109/README.md) |
| HPM6800EVK | RISC-V JTAG 25 MHz。记录 DTM idle、TDO 模式及所用 SRAM 区的缓存属性。[实测](validation/hpm6800-workbench-acceptance-20261109/README.md) | 不适用 |

除 ETM 专用的 SWD 10 MHz，每条链路只用表中一个档位。记录实际 FCLK、SWCLK/TCK 及其来源，注明是寄存器推算还是仪器测量。所选实际档位未达到时，记录实际值及原因，并把指定档位标为待验或失败。历史报告用于选档；每次接受新的板测结论都要对应实际配对和本轮证据。

开测前确认 ZynqLinkPRO J7 的 USB 序列号、当前 COM（如用）、bit/探针 PS ELF、目标固件和探针占用状态。保存本轮会改变的 Flash、SRAM、核心寄存器和外设配置。结束时独立核对恢复、目标运行或暂停状态及探针采集引擎状态。

### J-Scope 判定

- F103ZE 和 H743 分别做 SWD 单路、SWD 八路、JTAG 单路、JTAG 八路，共四个 60 秒确认窗口。HPM6800EVK 做 JTAG 单路和八路，共两个。各路使用相同宽度的已知数据，例如每路一个 u32。
- 固定链路档位，从已有稳定点附近短窗调整**采样周期**，只对单路和八路各取最快通过点做 60 秒确认。长窗失败时保留该证据，放宽周期后重新确认。
- 60 秒内探针跳拍率须严格低于 0.1%，USB 丢包、数据帧序号缺口、读错和 STOP 尾差均为 0。记录请求周期 ticks、实际收到的完整样本组数、实得组/s 和跳拍率。八路按一组八值计。分别保留测速窗和含 STOP 的会话最终计数。

### 性能记录

使用同一探针配对、目标固件/时钟、负载、数据量、窗口和重复次数。记录实际执行入口和传输方式，给出有效数据量、用时、单位及同口径历史差值。SRAM、烧录和 RTT 转发按表做 Web / 原生 CLI 对照。RTT Viewer 记浏览器实收，有同等轮询负载的原生工具时可并列；J-Scope 记实际采样路径及采样组率，ETM 记各阶段耗时。由 CLI 驱动 Web 页面时，结果归入 Web。为性能与功能分别保留判据和结果。

## 跨页与断线压力测试

每块板在每条适用链路的固定档位各做 **3 轮**。在同一 Web 工作台会话中，每轮把 **RTT Viewer、RTT 转发、J-Scope、调试**各跑一次，顺序随机且三轮不同。启动后确认上行有连续序号、采样有已知值或调试已经暂停并可读 PC，再执行该次切换或断开。采样和收数使用短窗。

每轮给四项业务各分配一种结束方式，跨轮轮换对应关系，让同一种断开落到不同业务上。安排第 3、4 种在三轮中分别覆盖 RTT 收数中、J-Scope 采样中和调试暂停。

1. 正常停止或退出当前业务，直接切到另一页启动业务。
2. 正常停止或退出后，在空闲态点断开，再连接。
3. 工作中点断开，再连接。
4. 工作中断开 J7 的 USB 数据连接，再接回。已确认可操作且能保持探针与目标供电时执行，否则将物理断线项记为待验。串口重新枚举后按 J7 序列号核对实际 COM。

每次重连后，先验证断开前的业务可重新启动并收到新数据或完成一次暂停/单步，正常退出后再继续轮换。正常停流核对序号连续，RTT 转发和 J-Scope 另核对 STOP 尾量。故意断线时保留中断状态和可验证的数据边界，重连后的新会话须无旧包、无卡死、无上一业务占用残留且数据继续前进。调试断开后核对目标实际运行或暂停状态，清除本轮临时断点。三轮结束后核对目标恢复、探针空闲及下一次连接可用。

记录每轮实际顺序、各业务对应的结束方式、重连耗时、异常和恢复结果。若使用脚本打乱顺序，同时保存随机种子。首次异常保留步骤和日志，刷新、重启或重载后的结果单列。

## 一键执行

在仓库根目录预览计划。可用 `--transport` 和可重复的 `--only` 选范围，`--seed` 复现随机顺序。

```powershell
python -X utf8 toolbox.py project run board.accept -- --board f103ze
```

为本轮启动独立的本机源码工作台。下例使用 J7 的正式 QSPI 配对，临时加载配对时同步替换两个路径。打开服务输出的鉴权地址并保留一个工作台标签页。

```powershell
python -X utf8 toolbox.py --runtime build/accept-web-f103 serve --native-probe --bit prebuilt/qspi-release/probe.bit --zynq-elf prebuilt/qspi-release/application.elf
```

另开终端执行。以下示例针对已确认运行 CDC48、原 SWJ_CFG 为 2 的 F103ZE，授权擦写并复位目标时才加 `--allow-flash`。

```powershell
python -X utf8 toolbox.py project run board.accept -- --board f103ze --runtime build/accept-web-f103 --out build/accept-f103-new --f103-restore-swj 2 --allow-flash --execute
```

- 每条用例和每一压力轮都即时输出 JSON 行。目录中有增量 `events.jsonl`、总表 `summary.json`、各项原始证据和私有恢复备份。可恢复的失败继续后续项目。恢复或写入结果未确认时剩余项记为阻塞，并输出总表。退出码 `0` 表示所选范围通过，`1` 表示有失败或阻塞，`2` 表示仍有待验。全范围通过才设置 `accepted=true`。
- 默认匹配 J7 序列号 `12345678`，COM 按序列号动态发现。AP0 身份和时钟检查需要 XSCT 及一个可唯一定位的 Zynq Cortex-A9，支持 `--sdk`。现有 ETM 原生采集还要求只有一只同 VID/PID 的探针在线，有歧义时 ETM 记待验。
- 烧录使用与板上相符的 `--target-elf`，备份涉及的扇区及算法工作区，并对照真实 Web 和原生 OpenOCD。HPM 原生烧录需传对应 SDK 的 `--openocd` 与 `--openocd-scripts`。本入口测试重新烧录原应用，独立读回后执行软件复位并查心跳。H743 的 ETM 需先在 CPU60/TRACE20 基线上执行 `--only etm` 补测，脚本把当前 ELF 不匹配的情况列为待验。
- ARM/JTAG 的 RTT 转发和 J-Scope 可以运行原生对照。当前 Web 只提供 ARM/SWD 和 RISC-V/JTAG 流模式，ARM/JTAG 网页和相应跨页动作为待验。J-Scope 的 60 秒窗口报告最快通过的已试周期，并保留短窗与长窗失败点。
- 物理断线默认记为待验。能保持探针和目标供电时，交互终端可加 `--usb-data-cycle`，按提示拔插 J7 数据线，程序确认消失和重新枚举后继续。

各板分开执行，换板后使用新的证据目录。最后给出全部结果目录，包括 H743 单独的 ETM 补测目录，离线汇总判定。汇总使用相同的源码提交和探针对，按用例选择最新结果，原报告保留首次失败和重跑记录。

```powershell
python -X utf8 toolbox.py project run board.accept -- --review build/accept-f103-new build/accept-h743-new build/accept-h743-etm build/accept-hpm-new --out build/acceptance-review
```
