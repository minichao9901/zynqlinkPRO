# SWD 低频：高电平宽度对照（2026-10-29）

后续已完成当前 F103CB/接线下的生产窄脉宽功能修复验收，见[修复验收记录](SWD窄脉宽修复验收-20261029.md)。本文保留此前独立实验与旧配对的历史状态。尚未测量目标 MCU 端的模拟波形，不能把“额外时钟边沿”当成已证实原因。

## 有效对照

独立 PS/AXI GPIO 工程绕过 USB、DAP、生产 SWD/JTAG FSM。一个 ODDR 同时提供普通和短高电平模式，使用相同引脚、驱动强度（SLOW/4）、输出原语和布线。每次按 direct → short → direct 测试，目标 Flash 未改写。

| 实际 FCLK | 短模式请求的高电平 | 标称位速率 | direct / short / direct |
| --- | --- | --- | --- |
| 99,999,999 Hz | 约 5 ns | 10 kHz、100 kHz、1 MHz | 三档均 FAIL / PASS / FAIL |
| 49,999,999.5 Hz | 约 10 ns | 10 kHz、100 kHz、1 MHz | 三档均 FAIL / PASS / FAIL |

短模式的每次 PASS 同时要求 ACK=1、DPIDR=0x1BA01477、parity 正确。普通模式通常是 ACK5 / FE3F019F；一次返回 F8DE033B，仍为错误。每次物理 pad 数字计数都为预期 200 个上升沿。标称位速率不包含软件/MMIO 开销；高电平数值来自 ODDR 请求及实际时钟寄存器，不代表 MCU 端模拟脉宽测量。

配对和 SHA-256：`prebuilt/20261029_swd_pulse_width_control/manifest.json`。原始数据：`results/swd/pulse_width_20261029/pulse5_actual100.json`、`pulse10_actual50.json`。

生产 FPGA 配上不含 USB/DAP 的最小 PS 驱动，实际 FCLK50MHz，仍在三档低频复现 ACK5 / FE3F019F。这排除了后台 USB/DAP 固件作为必要触发条件。该配对和日志也在上述目录中。

## 纠正之前的脉宽标注

此前独立工程约束为 100MHz，但旧加载器仅执行 `prebuilt/ps7_init.tcl`，将 FCLK 设置为 IO PLL / (6×6)，实际约 50MHz。旧的单 FCLK 短脉冲实际约 20ns，不能称为 10ns。

新固件记录 FCLK0、IO PLL、ARM PLL 寄存器。新加载器明确设置 50/100MHz，报告实际计算值。旧 manifest 已追加更正；旧 bit/ELF 和原始日志保留。STA 的 100MHz 约束与实际加载后的运行时钟必须分开解释。

## 生产工程探测版本

`prebuilt/20261029_swd_main_clock_observer/slow4.bit` + `probe.elf` 已实际加载。此配对保留被动 JTAG/SWD trace，并在 F8/FC 加入时钟 pad 计数。实现通过 120MHz 时序检查（setup +0.272ns、hold +0.042ns），实际交付哈希见同目录 manifest。

SLOW/4 在实际 SWCLK34.615384、49.9999995、59.999999MHz 通过两轮 1024-byte 随机 SRAM 写读，原 SRAM 恢复验证通过，RCC 未变。0.25/1/10/25MHz 仍失败。低频失败 DPIDR 的 pad/intended 上升沿计数均为 13，高速成功时均为 47。SLOW/16 对照曾在初始 1024-byte 备份读取时失败；不作为默认配置。该实验配对尚未做 JTAG 回归。

计数相同只能约束 FPGA 端可见的额外边沿，不能证明 MCU 端没有短脉冲。相位比较 sticky 位也会在正常短脉冲或成功高速访问中置位，因为 pad 传播延迟可能超过请求的高电平；不能单独据此认定额外时钟。

## 当时剩余工作（已完成后续功能验收）

先在真实 CM3 仿真中验证：保持低位速率时，用较高 FCLK 和分频等待产生窄高电平，覆盖 ACK、AP、TransferBlock 与 SRAM 数据；再生成新配对进行板测。生产路径当前的传输等待字段仅 4bit，若固定较高 FCLK，需要扩展等待范围以覆盖 250kHz，不应偷偷提高最低频率或只修 DPIDR。

数据相关的额外推进模型（每段连续 0 少一位）与旧读回吻合，且能解释为何较短高电平可能消除故障，但仍只是机制假设。后续完成了生产路径、低频分频扩展和配对板测，模拟原因确认仍未完成，不能将功能验收等同于物理机制确认。
