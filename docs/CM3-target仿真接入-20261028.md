# CM3 target 仿真接入（20261028）

## 1. RTL 来源

`https://gitee.com/zdevt/cortex_m3_on_xc7a100t`，克隆到 `reference/cortex_m3_on_xc7a100t/`（`reference/` 被 `.gitignore` 忽略，不入库）。

真正可用的核在：

```
reference/cortex_m3_on_xc7a100t/cm3_core/Arm_ipi_repository/CM3DbgAXI/rtl/
```

17 个文件，全部是 **Xilinx IEEE-1735 加密**（`pragma protect` / AES128-CBC），
`cortexm3_integration.v`、`cm3_dpu.v`（1.2 MB）、`dapswjdp.v` 等都在里面，
IP 顶层模块为 `CortexM3DbgAXI`，96 个端口（SYS/CODE 两个 AXI3 主口 + 独立调试口）。

同一路径下的 `Cortex-M3-DesignStart-Eval` 是另一种东西：`CORTEXM3INTEGRATIONDS.v`
只是 SystemC cycle model 的包装，真核在 `libcortexm3_integrationds_dsm.a` +
`libcarbon5.so`（Linux ELF），本机跑不了。**不要拿它当 RTL 用。**

## 2. 为什么只能用 XSim

iverilog 无法解密 IEEE-1735；Vivado 2018.3 的 `xvlog/xelab/xsim` 可以。
`tools/run_cm3_sim.py` 负责搭环境（`RDI_DATADIR`/`XILINX_VIVADO` 等）、
编译 RTL + 本仓库的 `fpga/sim/*.v|sv`、elaborate、跑仿真。

```powershell
python tools/run_cm3_sim.py --top tb_cm3_smoke
```

`--rtl` 或环境变量 `CM3_RTL` 可指向别的 RTL 目录。

## 3. 新增文件

| 文件 | 作用 |
| --- | --- |
| `fpga/sim/axi3_sram.v` | 行为级 AXI3 从机内存（单笔未完成、INCR、32 位），给 SYS/CODE 两个主口用 |
| `fpga/sim/cm3_target.sv` | 包 `CortexM3DbgAXI` + 两块 AXI3 SRAM，引出 `SWCLKTCK/SWDITMS/TDI/TDO/nTDOEN/SWDO/SWDOEN` |
| `fpga/sim/tb_cm3_smoke.sv` | 直接驱动 TAP，复位后读 IDCODE |
| `tools/run_cm3_sim.py` | XSim 编译/运行封装 |

## 4. 已验证

`tb_cm3_smoke`：TAP 复位 → IR=IDCODE(0xE) → 32 位移位读出

```
JTAG IDCODE = 4ba00477
PASS CM3 JTAG IDCODE 4BA00477
```

说明加密核在本机的 XSim 下能正常解密、elaborate、响应 TAP 扫描。
注意 TDO 采样点：要在 TCK 下降沿之后取（`tick()` 里先 `tck=1; #5 tck=0; #5 r=tdo;`），
在上升沿之前采样会整体错一位（首版读出 `0x974008EF`，正好是 `0x4BA00477<<1|1`）。

## 5. 下一步

1. `tb_cm3_swd`：把 `swd_controller` 接到 CM3 的 SWD 口（`SWDITMS`/`SWCLKTCK`/`SWDO`/`SWDOEN`），
   跑 DPIDR → AP 读写 → HSS/RTT，多速率扫描；
2. `tb_cm3_jtag`：接 `TDI`/`TDO`/`TMS`/`TCK`，用 `jtag_core` 跑同一套；
3. 与 `d42b601`（SWD）和 `902e228`（JTAG）的周期数对比，确认没有退化；
4. 核里不执行程序：CODE 口全 0，核取指后进 fault，不影响调试口和 MEM-AP。
