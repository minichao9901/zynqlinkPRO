# HPM5301EVKLite 性能基线（2026-10-29）

本轮先打通 PL DMI/SBA，使原有 PL RTT/HSS 数据通路能访问 RISC-V。目标运行 SRAM 测试程序，CPU 360 MHz / AHB 120 MHz；周期计数器对照 24 MHz 定时器实测约 360 MHz。未改写目标 Flash。

这是一份后续提速的对照基线，当前每次 DMI 访问均采用“请求 + NOP 收回应”两次扫描，尚未采用 superlinkPRO 的每字一次 DMI 流水快路径。

每个通过档位还做了 3 轮 4 KiB 随机写读、非对齐读。64 KiB 测量窗口位于 DLM 系统地址 `0x0106C000`，避开测试程序数据/堆栈；SBA 线性增址，每 32 个请求重设地址，不依赖 ARM TAR 回绕。所有读取逐字节检查，写入回读比较，原窗口恢复验证通过。

25 MHz 的短块/吞吐测试可通过相位 17，但冷连接出现失败；采用实际 24.324324 MHz、相位 0 作为稳态基线。30/40/50/60 MHz 逐相位连接或校验未通过，未作为有效性能。失败档位的实际 FCLK/TCK 在原始 JSON 中。

## 连续复核

实际 TCK 24.324324 MHz 持续 30.28 秒，68 组读写，所有读字节和写后回读均一致，0 错误，原 SRAM 恢复一致。读中位 0.767 MB/s，写中位 0.765 MB/s。目标计数器主频前/后实测 359999400 / 360000899 Hz。

## 配对、时序与修复

- 源码快照：`69f0bf4522ed15893d9afd9919d017ce3bdb4a4d`；构建时为前序提交加工作区修改，提交后逐项核对 RTL/固件源文件哈希与构建清单一致。
- 实际加载：`prebuilt/20261029_hpm5301_riscv/probe.bit` + `probe.elf`；目标 SRAM ELF 为同目录 `hpm5301_perf.elf`。完整 SHA-256、构建选项和验收范围见该目录 `manifest.json`。
- 时序 FCLK 120 MHz：setup +0.119 ns，hold +0.042 ns；探针内部时序通过不代表目标能在 60 MHz 通信。
- IDCODE 指令移到 JTAG_ROUTE[15:8]，避开 IR_AFTER 的 [29:19]；bit2 选择 RISC-V 内存前端。
- HPM 的 IDCODE/DTMCS 与 DMI 之间补 TAP reset，并重新选择 IR=0x11、激活 DM；连接/重试可能改变 halt 状态，因此性能表只报告心跳复核后的 running 状态。
- DTMCS=0x7071：abits=7、idle=7；PL 对 DMI 强制至少 8 个 idle，虽然共享 CSR 的普通 idle 字段仍读到 1。
- ARM JTAG 全流水线、生产 C 测试和 RISC-V 完整 PL RTT/HSS/错误围栏仿真通过；本配对未做新的 ARM 实板回归。
