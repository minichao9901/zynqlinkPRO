# JTAG 基础后端合并到 main（20261028）

来源：`902e228`（tag `probe-jtag-baseline-20261027`），从 `d42b601` 分出的 8 个提交。
按交接文档的建议，取 **base 后端 + 整数分频 PHY + IDDR 相位闭环**，不取 `codex/probe-jtag` 后面的 Q16 发生器、链式校准和 32 MHz 上限。

## 2. 冲突与解决

只有 `DAP_vendor.c` 冲突：两边都占了 vendor `0x89`。

- **0x89 归 JTAG**（时序位 + scan 统计，`jtag_*` 系列主机工具依赖它的返回布局）；
- **SWD 接收边界命令移到 0x8A**（原 0x89 的实现整体搬过去，语义不变）；
- 同时删掉合并后重复的 `case ID_DAP_Vendor10: break;`（先编译时被 `-Werror` 之外的 duplicate case 抓出来）。

`DAP.c`、`swd_controller.v`、`DAP_config.h`、`tb_cortexm0_link.sv` 都是自动合并；逐处核过：SWD 的 RX 边界 bit18、PLL 返回值检查、按实际频率选 Q1/Q2 都保留，JTAG 的 `DAP_JTAG_ClockChanged()` 钩子接在 `Set_Clock_Delay` 之后。

## 3. 行为变化

- `DAP_Connect` 现在能返回 JTAG（前提是 `FEATURES` bit3 置位；由 RTL `0x4450_000F` 提供）。
- 引脚由 `JtagConfig[1:0]`（0x80）选择：`route=3` → TCK/TMS/TDI/TDO，`route=2` → SWCLK/SWDIO。`PORT_JTAG_SETUP` 会把 `SWD_CFG` 改写成 `(1<<0)|(1<<4)`，切回 SWD 后由 `DAP_SWJ_Clock` 重新设置 `delay_fast`/`sample_rise`，bit18 保持清零。
- AXI 地址从 7 位变 8 位：外部按旧 7 位窗口访问的主机需要同步；仓库内 firmware/BSP 由新头文件驱动，无需改动。

## 4. 验证

本机执行：

- `tools/test_jtag_rtl.py`：JTAG 全流水线（pad mux、AXI、自主 HSS、posted 时间戳、包错误围栏、不可变 bank、RTT 1 KiB 非对齐拆分、DDR-before-RdOff）**PASS**
- `tools/test_probe_rtl.py`（3 项）、`tools/test_packet_engine.py`（6 项）**PASS**
- `tools/run_swd_rx_wire.py`（18 项）、`tools/simulate_swd_ack.py`（4 项）**PASS**，SWD 路径无回归
- `tools/test_probe_host.py`（4 项，含新增的 JTAG 校准用例）**PASS**
- 固件编译：`build_xusbps_daplink.py --project xusbps_daplink_dma --opt 0` 通过，产出 `build/xusbps_daplink_dma/O0/xusbps_daplink_dma.elf`（717,600 B）

## 5. 后续

- JTAG 的下一步改动（Q16 时钟发生器、链式校准、32 MHz 上限、粗采样 offset、诊断入口）都在 `codex/probe-jtag`，与本提交的共同祖先就是这里，建议逐条 cherry-pick 而不是整包 merge。
- 若将来合 `codex/swd-timing-generator`，注意它的 `swj_clk_gen.v` 与 JTAG 分支同名但端口/语义不同，不能直接选 ours/theirs。
- `feature/swdio-idelay` 的 CFG[22:18] 与本次 SWD 的 bit18 边界位有重叠，移植时要重新分配。
